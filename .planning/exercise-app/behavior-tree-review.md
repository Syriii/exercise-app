## 1. 核对标记

- **主干：** 删除后页面失去存在意义。
- **分支：** 只在明确场景下需要，但仍帮助用户完成页面根目标。
- **叶子：** 详情、解释或异常处理，应按需展开。
- **候选剪枝：** 没有独立用户目标，或存在更简单的替代路径。
- **后台：** 系统必须保留，但用户不需要理解或维护。

每个页面统一核对五件事：

1. 用户为什么进入这个页面；
2. 进入后首先需要判断什么；
3. 用户可以采取哪些动作；
4. 动作完成后产生什么结果；
5. 哪些枝叶不能回到页面根目标。

## 2. 全 App 行为根

```text
打开 App
├─ 处理今天
│  ├─ 记录饮食
│  └─ 记录训练
├─ 回看或改错
│  └─ 历史
└─ 查看或修改个人信息
   └─ 我的
```

当前判断：全 App 的三个根目标是“处理今天、回看改错、查看或修改个人信息”。训练与饮食是处理今天的两条执行流程；历史负责回顾，我的负责身体数据、资料目标与低频设置。

### 全 App 页面关系总审草案

```text
首次进入
├─ 登录或注册
├─ 完成基础资料、初始身体记录和目标方向【必填】
├─ 设置提醒【选填，可跳过】
└─ 进入“今天”

日常进入“今天”
├─ 饮食卡
│  ├─ 查看今天已摄入四项营养
│  ├─ 拍照记一餐 → 饮食页唯一拍照流程
│  │  └─ 识别、必要时修改、保存 → 更新饮食页和今天页
│  └─ 上一餐 → 饮食页当天餐食列表
├─ 训练卡
│  ├─ 有计划 → 显示计划、已记录和剩余动作
│  ├─ 无计划 → 显示今天实际训练摘要
│  └─ 记录训练 → 训练页记录区
│     ├─ 从计划、最近记录或空白建立草稿
│     └─ 批量填写并保存 → 更新训练页、今天页和历史
└─ 身体测量到期提示【仅到期出现】
   └─ 记录测量 → “我的”下的身体数据页

五个一级入口
├─ 今天：只做今日摘要和快捷分流，不维护详情
├─ 饮食：记录餐食、查看当天餐食、管理饮食功能
├─ 训练：管理训练计划、记录实际训练
├─ 历史：查看记录与趋势，并进入原业务记录改错
└─ 我的：查看身体数据和目标，并进入低频应用或账号设置
```

快捷入口只携带日期、目标区域或目标记录等上下文，实际新增与编辑仍由饮食、训练和身体记录各自的一套流程完成。保存餐食或训练后留在对应业务页，用户返回“今天”时看到刷新后的摘要；从历史进入修改时，保存后返回原日期位置。

“身体数据”是“我的”下的二级业务页面，不增加第六个一级导航：它负责新增、查看、修改和删除体重或腰围记录，并展示身体趋势。首次设置中的身体资料创建第一条测量记录；以后每次称重都进入这里新增记录。历史页可以展示某日测量和趋势，但只作为回看入口，并跳转到同一身体数据页面，不承担唯一入口。

## 3. 登录与首次使用

**页面根：** 完成账号进入和必要的首次设置，让训练与营养核心能力拥有基本输入。

### 当前实际实现

```text
访问 App
├─ 未登录
│  └─ 登录或注册
│     ├─ 普通账号 → 返回原目标页；无目标时进入“今天”
│     └─ 预置密码账号 → 强制修改密码 → 再进入 App
└─ 已登录
   └─ 直接进入“今天”

新账号第一次主动进入“设置”
└─ 档案、策略和测量都为空时自动打开 4 步设置
   ├─ 1. 基础资料
   ├─ 2. 身体数据
   ├─ 3. 目标方向
   └─ 4. 三类提醒
      └─ 完成后回到设置目录
```

当前实现没有在注册完成后强制跳入设置，而是直接进入“今天”；用户只有进入设置时才会自动看到首次设置，并且可以使用“以后再设置”返回今天。登录/注册页本身只要求用户名和密码。

### 已确认行为链

```text
进入 App
├─ 已有账号
│  └─ 登录
│     ├─ 首次设置已完成 → 进入“今天”【主干】
│     └─ 首次设置未完成 → 进入首次设置【主干】
└─ 没有账号
   └─ 注册
      └─ 进入首次设置【主干】
         ├─ 1. 基础资料【必填】
         ├─ 2. 身体资料【必填】
         ├─ 3. 目标方向【必填】
         └─ 4. 提醒【选填，可跳过】
            └─ 进入“今天”
```

### 确认保留

- 注册、登录。
- 预置密码账号强制修改密码。
- 新用户进入正式使用前完成首次设置。
- 首次设置中的基础资料、身体资料和目标方向。
- 提醒作为首次设置最后一个选填步骤，并允许跳过。

### 确认修改

- 注册后不再直接进入“今天”，而是先进入首次设置。
- 不能从基础资料、身体资料或目标方向步骤直接退出首次设置；只有提醒步骤可跳过。
- 当前“以后再设置”不能继续用于跳过前三个必填步骤。
- 完成后的“按步骤检查”是否保留，归入设置页面核对，不在本页提前决定。

### 当前实现与建议逻辑的差异

| 项目 | 当前实现 | 建议逻辑 | 当前判断 |
|---|---|---|---|
| 注册后去向 | 直接进入今天 | 先完成首次设置，再进入今天 | 需要修改 |
| 首次设置触发 | 第一次主动进入设置时触发 | 注册后或首次设置未完成时触发 | 需要修改 |
| 首次设置内容 | 基础资料、身体数据、目标方向、三类提醒 | 前三项必填，提醒选填 | 结构保留，约束调整 |
| 首次设置跳过 | 任一步都可“以后再设置” | 前三项不可跳过，提醒可跳过 | 需要修改 |
| 完成后再次进入向导 | 设置首页提供“按步骤检查” | 留到设置页核对 | 暂不决定 |
| 密码安全 | 普通注册设密码；预置密码必须修改 | 保留必要账号安全 | 属登录主干，保留 |

### 核对结论

- 状态：已确认。
- 产品所有者纠正：首次设置必须存在；基础资料、身体资料和目标方向为必填，提醒为选填且允许跳过。
- 确认保留：登录、注册、强制改初始密码、首次设置四步结构。
- 确认下沉：提醒不作为必填资料，只放在最后一个可跳过步骤。
- 确认删除：跳过前三个必填步骤的“以后再设置”路径。

## 4. 今天页面

**页面根：** 让用户马上知道下一步可以做什么。

### 当前实际实现

```text
进入“今天”
├─ 页面头部
│  └─ 安排或开始训练
├─ 到期提醒（最多同时出现三类）
│  ├─ 训练提醒 → 查看 / 一小时后提醒 / 今天不再提醒
│  ├─ 饮食提醒 → 查看 / 一小时后提醒 / 今天不再提醒
│  └─ 身体测量提醒 → 去记录 / 明天提醒 / 本次不再提醒
├─ 今天还可以吃
│  ├─ 能量、蛋白质、碳水、脂肪的剩余和已记录值
│  ├─ 全天覆盖确认或“只统计已记录餐食”说明
│  ├─ 当前采用的体重日期
│  ├─ 缺资料时进入设置
│  └─ 去记一顿
├─ 今天还要练
│  ├─ 进行中 → 展示待完成动作并继续训练
│  ├─ 有安排 → 开始或取消安排
│  └─ 无安排 → 进入训练页安排或直接开始
└─ 今天已经记录
   ├─ 展示已完成或提前结束的训练
   └─ 查看历史
```

```text
进入“今天”
├─ 查看饮食状态【主干】
│  ├─ 今天没有记录
│  │  └─ 拍照记一餐
│  ├─ 已有记录
│  │  ├─ 查看大致摄入和剩余
│  │  └─ 继续记一餐
│  └─ 发现错误
│     └─ 进入饮食页修改【分支】
├─ 查看训练状态【主干】
│  ├─ 有进行中的训练
│  │  └─ 继续训练
│  ├─ 今天有准备训练
│  │  └─ 开始训练
│  └─ 没有安排
│     ├─ 使用上次或常用方案
│     └─ 空白开始
└─ 查看今天已经完成的内容【分支】
   └─ 进入历史详情
```

### 当前保留判断

- 今天已经摄入的能量、蛋白质、碳水和脂肪，以及“拍照记一餐”。
- 当前训练状态和“继续/开始训练”。
- 今天已经完成内容的简单摘要。

### 当前剪枝候选

- 训练、饮食和身体测量三张页面内提醒卡片。
- “一小时后再提醒”“今天不再提醒”等首页提醒管理。
- 与历史重复的完整完成记录。
- 首页上的记录完整性、计算方法和数据来源说明。

### 当前实现与建议逻辑的差异

| 区域 | 当前实现 | 建议行为 | 当前判断 |
|---|---|---|---|
| 页面头部 | 单独提供“安排或开始训练” | 训练动作只在训练卡内出现 | 与训练卡重复，建议删除 |
| 提醒 | 最多三张完整操作卡 | 提醒不与首页主干竞争；浏览器通知继续存在 | 训练/饮食提醒与主卡重复，建议移出主结构 |
| 饮食概况 | 四项剩余、已记录、完整性、体重日期、补资料 | 只显示今天已经摄入的四项营养 | 剩余量、完整性、体重日期和补资料入口均不属于今天页 |
| 今日餐食入口 | 单独“去记一顿”，没有上一餐摘要 | 保留“拍照记一餐”；上一餐时间同时作为进入今日餐食列表的入口 | 不再增加独立“查看饮食详情”链接 |
| 有今日计划 | 按进行中、已安排状态分别展开动作和操作 | 只显示计划名称、已完成项数和剩余项数 | 不在今天页管理计划或展开动作 |
| 无今日计划 | 只显示“今天还没有训练安排” | 直接显示今天实际训练过的内容；尚未训练则显示无记录 | 首页关注事实，不要求先有计划 |
| 训练入口 | 随状态出现开始、继续、取消等多个动作 | 固定提供一个“记录训练”入口 | 进入训练页的记录区；不创建进行中状态 |

### 建议行为链

```text
进入“今天”
├─ 饮食【主干】
│  ├─ 查看今天已经摄入的能量、蛋白质、碳水和脂肪
│  ├─ 拍照记一餐【主动作】
│  └─ 上一餐：时间 + 餐次名称【分支，同时是进入今日餐食列表的入口】
│     ├─ 有记录 → 例如“上一餐：12:30 午餐” → 进入饮食页当天记录
│     └─ 无记录 → “今天还没有记录餐食”，不额外制造详情入口
├─ 训练【主干】
│  ├─ 有今日计划
│  │  ├─ 显示计划名称
│  │  ├─ 显示已完成多少项
│  │  └─ 显示还剩多少项
│  ├─ 没有今日计划
│  │  ├─ 今天有实际训练 → 简单列出训练过的内容
│  │  └─ 今天没有实际训练 → “今天还没有训练记录”
│  └─ 记录训练【统一入口，进入训练页的记录区】
└─ 可选提醒【叶子】
   ├─ 训练和饮食状态不再重复生成大卡片
   ├─ 浏览器通知继续按用户设置触发
   └─ 身体测量到期时可显示一条轻量提示
```

### 核对结论

- 状态：已确认。
- 产品所有者纠正：饮食卡只显示今天已经摄入的四项营养、拍照记一餐和上一餐时间；上一餐这一行同时作为进入今日餐食列表的入口。训练卡不按进行中、安排、完成拆出复杂状态：有计划时只显示计划名称、完成多少和剩余多少；没有计划时直接显示今天实际训练了什么；统一入口按训练页最新两对象逻辑改为“记录训练”。
- 确认保留：饮食与训练两张主卡；拍照记一餐；上一餐时间入口；计划名称与完成/剩余摘要；无计划时的今日实际训练摘要；统一记录训练入口；浏览器提醒与身体测量轻提示。
- 确认下沉：餐食列表和修改进入饮食页；训练动作、训练过程、计划管理和历史细节进入训练或历史页；提醒不占据首页主结构。
- 确认删除：今天页饮食剩余量、餐食完整性、采用体重日期、单独饮食详情链接、头部重复训练按钮、训练/饮食大型提醒卡、训练状态管理、完整动作列表、取消安排和独立已完成训练卡。

### 基本功能完整性检查

- 今天发生了什么：饮食卡显示今日已摄入营养和上一餐；训练卡显示今日计划进度或实际训练内容。
- 现在能做什么：饮食卡可直接拍照记一餐；训练卡可直接进入记录实际训练内容。
- 去哪里处理细节：上一餐行进入当天餐食列表；训练入口进入训练执行页；历史和设置继续由全局导航承接。
- 低频但可能到期的事项：身体测量只在到期时显示一条轻提示，不长期占据概览页。
- 结论：上述结构已经覆盖概览页的基本功能。手工记餐、常用食物、修改餐食、训练计划管理、训练记录细节、历史和设置都属于下一级页面能力，不需要在概览页重复出现。

## 5. 饮食页面

**页面根：** 快速记录吃了什么，并查看今天的大致摄入。

> 当前状态：整体复核中。已完成真实代码对照和三轮产品所有者纠正，尚未最终确认本页。

### 当前实际实现

```text
进入饮食页
├─ 快速记餐
│  ├─ 餐次名称、时间、备注
│  └─ 可选照片
├─ 系统参考
│  ├─ 四项营养目标
│  ├─ 档案与策略入口
│  └─ 计算依据与限制
├─ 我的饮食安排
│  ├─ 新建、编辑、归档日期范围计划
│  └─ 为日期和餐次填写准备怎么吃
├─ 还可以吃
│  ├─ 四项剩余量与已记录量
│  ├─ 数值完整或有未知值
│  └─ 今天吃过的内容都已记录
└─ 这一天吃了什么
   ├─ 管理所有常用食物
   └─ 每顿餐食都完整展开
      ├─ 常用食物快速添加
      ├─ 最近餐食按项复用
      ├─ 拍照、上传、分析与重试
      ├─ 模型、规则、置信度、假设和原图删除
      ├─ 暂定或确认状态、修正与拒绝
      ├─ 个人记录与公开包装食品搜索
      ├─ 单项、整餐或补充模式手工录入
      └─ 替代现有内容、保存为常用项或删除整顿
```

当前页面把概况、计划、记录、复用、图片任务、食物搜索、手工编辑、常用项管理和系统审计同时铺开。即使每项能力单独成立，用户也无法先看见一条稳定的日常主线。

### 建议行为链

```text
进入饮食页
├─ 今日概况【主干】
│  └─ 能量、蛋白质、碳水、脂肪：已摄入 / 每日参考
├─ 记录一餐【主干】

│  │  │  ├─ 正确 → 完成
│  │  │  └─ 不正确 → 修改食物、份量或营养
│  │  └─ 识别失败 → 简短提示 → 重试或进入“添加食物”
│  └─ 添加食物【主分支，统一选择入口】

│     │  └─ 输入关键词 → 显示匹配食物

   ├─ 默认只显示餐次、时间、食物名称和营养小计

      ├─ 修改食物或份量
      ├─ 添加或移除食物
      └─ 删除整顿餐食
```

建议将系统每日参考与已摄入合并为一个四项概况，不再分别展示“系统参考”和“还可以吃”两块。每顿餐食默认收起，只在用户主动打开时出现修改能力；记录入口也不再依赖用户先建立一个空餐次，再在餐次内部寻找拍照、复用或手工入口。

“添加食物”不是要求用户自己填写一组营养数值，而是一个统一食物选择器。未输入关键词时，结果区展示全部食物，只把用户常用食物排在前面，不把其他食物隐藏。用户可以按统一分类浏览整个数据库，也可以输入关键词搜索；分类作用于全部食物，不按普通食物、包装食品或数据来源拆成不同搜索系统。用户选中具体食物后只需填写克数或份量，系统换算营养并加入当前餐食。

食物数据库保存统一分类、食物名称、可搜索别名、营养基准和可用份量单位；品牌、包装和外部来源仍可以作为食物属性，但不产生另一套入口。用户使用次数、最近使用时间和习惯份量只影响同一结果列表的排序，不会再复制出另一套“个人模板食物”。加入餐食后仍保存当时的独立快照，避免数据库后来更新时改写历史记录。

### 页面结构整体复核

```text
饮食
├─ 页面头部
│  ├─ 当前日期
│  └─ 切换日期【低频，用于查看或补记】
├─ 今日概况
│  └─ 能量、蛋白质、碳水、脂肪：已摄入 / 每日参考
├─ 两个记录入口
│  ├─ 拍照记一餐【首要动作】
│  └─ 添加食物【统一食物数据库】
└─ 当天餐食列表
   ├─ 餐次、时间、食物和营养小计
   └─ 点击餐次后修改、继续添加、移除食物或删除整顿
```

页面不要求先建立一个空餐次。拍照或添加食物时默认使用当前时间，并允许修改时间和餐次名称；完成第一项记录后自动形成该餐次。若用户从已有餐次进入“继续添加”，新食物直接加入该餐次。

### 两条记录流程

```text
拍照记一餐
├─ 拍照或选择图片
├─ 正在识别
├─ 成功 → 显示食物、份量和营养 → 计入当前餐次
│  └─ 有明显错误 → 直接修改
└─ 失败 → 重试或改用添加食物

添加食物
├─ 按统一分类浏览，或输入关键词搜索
├─ 默认展示全部食物，个人常用食物优先排序
├─ 选择一个或多个食物
├─ 填写各自克数或实际份量
└─ 加入新餐次或当前餐次
```

### 基本功能完整性检查

- 可以记录：拍照识别和数据库选择覆盖两条主要路径；识别失败仍可转入食物库。
- 可以快速复用：常用食物通过同一全量列表优先排序实现，不再维护重复的最近/模板区域。
- 可以找到食物：完整列表、整体分类和关键词搜索同时存在；默认不隐藏非常用食物。
- 可以核对结果：页面显示四项已摄入与每日参考，餐次显示食物和小计。
- 可以改错：餐次详情支持修改份量、继续添加、移除食物和删除整顿。
- 可以补记与回看：日期切换保留，但不与两个主记录动作争夺页面中心。
- 结论：这套结构覆盖饮食页基本功能；缺失的不是入口，而是需要实施统一食物数据库、分类和个人排序能力。

### 当前保留判断

- 四项营养的已摄入与每日参考，但合并为一块简单概况。
- 拍照识别、结果自动保存和直接修改。
- 统一“添加食物”选择器：统一分类、一个搜索框和一个结果区；空查询显示全部食物并把个人常用项排在前面。
- 选择食物后填写克数或实际份量，由系统换算营养。
- 今天餐食列表及修改、移除和删除。

### 当前下沉判断

- 食物分类作为统一数据库的整体浏览结构；品牌、包装和数据来源可以保留为属性，但不拆分成不同搜索入口或结果系统。
- 系统营养参考的计算依据放入设置或按需详情。
- 个人使用次数、最近使用时间和习惯份量由后台维护，用于生成常用建议，不要求用户管理另一套食物模板。
- 图片失败只在失败时显示重试；详细错误留在后台诊断。
- 查看过去日期保留在日期选择中，但不占主动作位置。

### 当前剪枝候选

- “我的饮食安排”。
- “今天吃过的内容都已记录”。
- 每项营养的“数值完整/有未知值”。
- 用户可见的“暂定采用/确认采用”、模型候选和采用值切换。
- 模型名称、提示词规则、置信度、完整假设列表和用户可操作的原图删除状态。
- 手工录入中的“单项/整餐/补充”“替代已有全部内容”等领域模式选择。
- 要求用户为常规食物直接手填四项营养值的默认路径；只有搜索不到食物时才考虑自定义条目作为异常补偿。
- 分开的“最近吃过”和“我的常用食物”区域及其重复数据。
- 分开的“普通食物”和“包装食品”搜索入口及结果分组。
- 用户可见的完整修订历史。

### 核对结论

- 状态：已确认。
- 产品所有者纠正：“手工添加”和食物搜索属于同一个选择食物流程，所有食物应由统一数据库提供；数据库拥有整体分类，不按普通食物和包装食品拆分搜索系统。未输入关键词时必须显示全部食物，常用食物只排在前面而不形成独立区域；用户选择食物后填写克数或份量。
- 确认保留：日期切换、四项已摄入与每日参考、拍照记餐、统一食物数据库的分类/全量浏览/搜索/常用排序、份量填写、当天餐食列表及修改删除。
- 确认下沉：数据来源、个人使用统计、图片任务、错误诊断和餐食快照由后台维护；日期切换、图片失败和详细修改只在需要时出现。
- 确认删除：饮食安排、全天覆盖确认、逐项完整性、最近/常用/包装食品分区、模型与采用状态、复杂录入模式、默认营养手填表单和用户可见修订历史。

### 2026-09-05 补充确认：拍照到单项食物复用

产品所有者在图片单项记录方案后回复“可以继续”，本主题按该方案确认；正式产品、领域与体验文档仍在整体讨论结束后统一同步。

- 拍照与手动选择最终形成同一餐内的单项食物记录，包含食物、实际份量及对应营养；可辨认的鸡蛋、豆浆分别记录，组合菜品可以整体作为一项，不强行拆成无法可靠辨认的原料。
- 拍照时默认当前日期和时间，允许修改并选填说明。上传成功后分析可在后台继续，用户可以离开；未得到的营养保持未知，不补零。
- 没有已有录入或修正内容时，识别成功自动保存单项结果并计入汇总，简短标记“照片估算”，不增加必经确认按钮。
- 份量修改按同一食物的营养基准同步换算；识别错食物时可以从统一食物库替换，也可补充漏项或移除多余项。“碗”等单位需要保留可解释的估算基准。
- 修改只作用于当前餐食，不覆盖食物库或历史记录。下一次从统一食物列表选择鸡蛋、豆浆等内容，可带出上次份量供修改；常用食物仍在同一列表前排，不增加独立复用页面。
- 失败可在原餐食重试或手动补充，不丢弃已有输入。重新分析不得静默覆盖手动修正，使用新结果时明确替换范围，避免与旧条目重复计入。
- 原图临时保留与清理继续由后台负责；取消必经确认按钮后，清理触发方式须在统一文档中一并明确，不将原图变成长期相册。

- 从今天计划、其他计划、最近记录或空白建立训练记录草稿。

- 查看、修改和删除当天已经保存的训练记录；同一天允许保存多次训练。
- 计划与记录可有关联也可无关联，双方互不反向覆盖。

### 当前下沉判断

- 动作指导继续作为计划动作或动作库详情中的按需内容，不建立训练中页面。
- 训练消耗估算。
- 系统建议作为“生成计划”的可选方式，生成后按普通计划处理。
- 计划编辑、日期安排和删除进入计划管理，不在训练首页展开所有卡片。
- 计划快照、来源关系、未完成/替换关系和消耗计算由后台维护或在详情中查看。

### 当前剪枝候选

- 训练首页长期展示系统草案及其证据、频率和适用范围。

- 用户需要维护的来源方案更新提示；从已有计划或实际记录创建计划的能力保留。
- 用户可见的“方案”“模板”“保存方案”等与计划重复的概念。
- 用户可见的计划动作、额外动作、跳过和替换的复杂对应关系。
- 每个动作同时填写次数、重量、时长和距离的统一大表单。
- 单次重复级实时计数和“5 / 12 次”式训练进度。

- “结束训练”“提前结束”和“继续训练”等围绕进行中状态的动作。

### 核对结论

- 状态：已阶段性确认。
- 产品所有者纠正：训练页不需要“结束训练”概念，也不需要以进行中训练为中心。页面只有两块核心业务：查看/修改计划，以及记录实际训练内容；记录可以从计划生成并建立关联，也可以完全独立于计划。“保存方案”与“计划”是重复的用户概念，界面统一只称“训练计划”。
- 确认保留：训练计划、当天训练记录、从计划/最近记录/空白批量填写，以及记录的修改删除。

- 确认删除：用户可见的方案/模板重复概念，以及开始、进行中、继续、结束训练和训练中逐组操作状态机。

### 2026-09-05 补充确认：批量记录与计划进度

产品所有者反馈“目前来看可以”，以下规则阶段性确认；仍不进入业务实现。

- 默认以动作整体录入，例如“3 组 × 10 次，40 kg”；各组不同时再展开调整。跑步等按适用类型填写距离、时长，不要求运动过程中逐组操作。
- 从今天计划、其他计划、上次记录或动作库建立同一编辑列表。带出内容只是草稿；用户可以按计划完成后直接保存，或先修改差异，整条记录一次提交，不逐动作提交。
- 保存前允许增删动作和修改实际量；忘记数量时可以只保存做过的动作，不拿计划值填补未知实际量。保存失败保留全部输入，成功后更新今天与历史，之后可修改删除。
- 从今天计划生成的记录自动对应原计划项，同一天多条关联记录可累计；从其他计划记录不自动安排到今天。独立录入或复用上次内容不因动作同名自动抵扣当天计划。
- 计划进度按明确记录量比较，例如力量动作按组数、有氧按所设时长或距离；不合并为跨计量方式的笼统百分比，也不把该进度解释为训练质量或强度达标。次数、重量等差异在训练页查看。
- 今天页保留完成与剩余摘要；部分记录和未记录须能区分，未记录不等于确定没练。只记录动作名称、没有数量时，不自动认定完成计划量。
- 多做的量保留但不抵扣其他动作；修改删除记录会更新关联进度，不反向改写计划。计划修改与已有记录的比较基准见下节已确认规则。

### 2026-09-05 补充确认：计划修改范围与日期安排

产品所有者反馈“可以”，以下方案确认；不新增“方案”“模板”等用户概念。

- “今天的计划”只修改当天动作、顺序和计划量，不改其他日期或可复用计划；允许改期和取消，但不移动或删除已经发生的实际训练记录。
- “我的计划”支持自己选动作、根据已有计划或实际记录创建、让系统生成后调整。计划可直接用于记录，不强制先安排日期。
- 修改可复用计划仅用于之后复用，不自动覆盖已安排日期。删除可复用计划不连带删除既有日期安排和实际记录。
- 安排到某日时生成独立安排；连续安排保留按周编排、各周不同的能力，放在“安排日期”深一层，不占据训练首页。合并方案与计划术语不等于删除多周安排。
- 已有实际记录后修改当天计划，实际量不变，当天进度按修改后的安排重新比较；保存处说明“将更新当天计划进度，已记录内容不变”，后台保留原比较依据。
- 只是实际少做时，用户直接记录少做的实际量，不必同步修改计划以求一致。

- 基础资料、目标方向及其逐项修改。
