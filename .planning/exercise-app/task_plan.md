# Exercise App 简明规划 v3

## 目标

先做一个真正适合个人日常使用的健身辅助 Web 应用；确认实用后开放给朋友，逐步完善为可开源、可构建并可安装为 Android APK 的项目。

## 已确认的项目基线

- 产品包含训练和饮食两个独立模块，两者共享必要数据。
- 训练方向包括计划、今日安排、动作指导、训练记录、消耗估算和提醒。
- 饮食方向包括每日营养目标、拍照估餐、摄入累计和饮食提醒。
- 实际训练情况会影响当天营养目标，但两个模块仍可独立使用。
- 食堂餐难以估算，是当前最重要的现实场景。
- 所有营养、热量和 AI 识别结果都属于估算，需要表达不确定性。
- 产品尊重用户自主性，不强制打卡或规定使用频率。
- 先做 Web，满意后提供 Android APK；先个人使用，再开放朋友和开源。

这些内容是重新规划的起点，不再通过重复提问重新确认。下一步先检查完整产品范围，而不是立即删减功能或设定使用指标。

## 工作方式

每个阶段只遵循四步：

1. Agent 先整理已经知道的内容。
2. Agent 给出完整方案或结构，不用连续小问题让用户从零设计。
3. 用户整体纠正、补充和选择。
4. 主题确认后再更新当前产品文档。

只有答案会改变当前产出，而且 Agent 无法采用安全、可逆的默认方案时，才向用户提问。验证用于检查产品是否有帮助，不用于考核或约束用户。

## Phase 5 当前实现范围

当前增量处理：

- 创建 `apps/server/` 模块化单体与 API、Worker 两个进程入口；
- 建立 PostgreSQL、Drizzle migration、pg-boss 和临时媒体接口地基；
- 建立预置管理员、常规注册登录、服务端会话和最小管理边界；
- Web 加入真实路由、客户端状态和类型化 API 边界；
- 建立 Docker Compose 开发骨架以及单元、集成、合约和端到端测试入口；
- 验证容器持久化、migration、任务事务性、密码不落明文和跨账号基础边界。
