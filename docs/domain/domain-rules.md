本文把已经确认的产品全貌变成能够支持后续体验设计和技术设计的领域规则，但不定义页面、数据库表、接口、框架、部署方式或首版开发顺序。

文中采用两种当前有效的规则等级：

- **继承规则：** 直接来自已经确认的 `docs/product.md`，本文不能擅自降低或删除。

本稿保留此前确认的证据与计算边界，并以 Phase 6.6 最新讨论替换记录、计划、页面和跨日规则。发生冲突时，以产品所有者最新明确表述和 `docs/product.md` 为准。公式与证据登记本轮不改；界面行为见 [体验设计](../experience/experience-design.md)，未实现能力见 [交付清单](../architecture/delivery-plan.md#phase-66-使用逻辑改造待实现)。

## 2. 领域全貌

产品由六个相互协作但职责独立的领域组成：

| 领域 | 主要责任 | 不负责 |
|---|---|---|
| 个人档案与目标 | 保存计算参考所需的个人状态、目标及其生效时间 | 替用户决定训练或饮食安排 |
| 训练 | 系统建议、用户计划、动作指导、实际训练、消耗估算 | 把训练计划冒充实际完成情况 |
| 饮食 | 每日营养参考、食物目录、餐食记录、摄入汇总 | 用训练提醒替代饮食提醒 |
| 图片分析 | 保存待分析照片、管理分析任务、候选结果、采用和修正 | 把模型输出表述为测量真值 |
| 当日并列视图 | 同时展示已记录营养和训练计划进度或实际摘要 | 用其中一项改写另一项，或合并训练与饮食任务体系 |
| 通用与安全 | 账号隔离、时间、修订、来源、提醒、数据控制和健康边界 | 提供诊断、治疗或绝对安全承诺 |

关系可以概括为：个人档案和目标产生系统参考；用户计划表达意图；训练与餐食记录表达事实；图片分析为餐食事实提供候选估算；当日页面只把已记录营养与训练摘要并列展示，二者互不改写。

## 3. 全领域共同规则

### 3.1 用户控制权

- **继承规则：** 系统训练建议不是命令，用户可以采用、修改或忽略；系统每日营养参考只作为参考，不建立独立饮食安排。用户也可以只使用部分能力。
- **继承规则：** 缺少记录不阻断程序使用，不产生强制补录、连续打卡或使用频率要求。
- **已确认规则：** 用户创建的计划、选择的策略和实际记录只能由用户主动操作或明确授权的规则改变；系统推导不得静默覆盖用户输入。

### 3.2 计划、事实和推导分离

- **继承规则：** 系统训练建议、用户训练计划和实际训练记录分别表达候选来源、用户意图和已发生情况；建议只有被用户采用或编辑后才复制为计划，训练主页不把建议与计划长期并列。
- **继承规则：** 系统每日营养参考与实际餐食分别表达系统推导和已发生情况；旧饮食安排不再属于当前业务流程。
- **已确认规则：** 系统每日营养参考属于规划基准，餐食照片分析属于实际摄入估算。图片识别质量不得改变参考目标的计算方法或准确性要求；只影响已摄入、剩余量和偏差结果的完整性与置信程度。
- **已确认规则：** 所有汇总结果都要能追溯到原始记录、采用的计算规则和当时有效的个人信息；推导结果不得反向改写原始记录。

### 3.3 时间与历史

- **继承规则：** 体重或目标变化从变更当天开始影响当天及以后，不重新计算过去日期。
- **已确认规则：** 每个与日期有关的记录都按用户当时设置的时区归属自然日；跨时区后，历史记录仍保留原归属日。
- **已确认规则：** 当天发生个人信息或目标变更时，当天当前参考可以重算，但旧参考作为修订历史保留；已经记录的训练和摄入不变。
- **已确认规则：** 修改历史训练或餐食属于用户主动修正，应重新汇总被修改的日期；这与后来体重或目标变化导致的“历史不回算”不同。
- **已确认规则：** 用户修正历史训练或餐食时，默认使用该日当时有效的档案、目标、数据来源和计算方法版本生成新修订，不自动换用当前档案或最新算法。未来若允许迁移算法，必须是显式操作并保留新旧结果。
- **已确认规则：** 训练与餐食保存用户选择的实际日期、大致时间及当时时区。跨午夜训练可按用户知道的实际开始日归属，未知精确开始时间不伪造；没有用户更正时保持草稿建立时的归属。主动改日期更新旧日和新日汇总，同一次事实不重复进入两天。

### 3.4 缺失、零值和不确定性

- **继承规则：** 数据不完整时应用继续可用，同时说明相关统计或建议受到的影响。
- **已确认规则：** “未记录”“未知”“待分析”“估算为零”和“用户确认为零”是不同状态，不能互相替代。
- **已确认规则：** 只汇总已知值；当关键数据缺失时，汇总必须同时标记完整性，不能把部分合计展示成完整摄入。
- **已确认规则：** 系统可派生已保存餐食的处理完整性，但不提供全天摄入覆盖确认。当天全部记录处理完也不能证明全天已记全，不能据此计算平均真实摄入或达标率。
- **已确认规则：** 能提供合理范围时，估算同时保留中心值与范围；不能提供范围时，至少保留置信等级、限制说明或未知因素。

### 3.5 来源、版本和修订

- **已确认规则：** 营养规划使用的每个公式、数值阈值、适用范围和安全边界都必须关联 `docs/domain/calculation-evidence.md` 中的证据记录，并能定位到官方文档的发布机构、标题、版本或日期及具体章节、表格或公式；只有二手摘要、博客或无来源惯例时不得进入自动规划核心。
- **已确认规则：** 产品自行形成的周预算守恒、日分配或约束求解规则必须列明官方输入依据和完整推导，标记为“产品推导”，不得表述成官方机构的直接结论。
- **已确认规则：** 计算结果保留输入快照、计算方法、方法版本、证据记录 ID、数据来源版本、生成时间和主要假设。
- **已确认规则：** 用户修正生成新修订，不抹掉模型原始估算或旧采用值；当前统计只读取被标记为当前的采用值，其历史修订仍可追溯。
- **已确认规则：** 引用的动作内容、食物营养数据和计算方法都要保留来源与许可状态，来源变化不能悄悄改写历史。

## 4. 核心业务词汇

本节只定义词汇。词汇中超出 `docs/product.md` 的粒度已经随 Phase 2 整体规则一并确认，其约束仍以对应规则章节为准。

### 4.1 个人与目标

| 概念 | 含义 |
|---|---|
| 用户账号 | 一名用户在系统中的独立身份及数据边界 |
| 当前个人档案 | 当前用于新建议和计算的身体与生活信息，如身高、出生日期、基础活动水平及公式确实需要的生理信息；页面不提供通用档案版本管理 |
| 身体测量记录 | 用户在某个时间记录的体重、腰围或其他身体测量事实；修改通过修订保留历史 |
| 当前健身目标 | 当前用于新建议和计算的结构化目标与偏好；体重策略影响营养规划，训练目标只在用户请求训练草案时作为明确选项收集 |
| 当前饮食策略 | 用户当前在系统支持且证据适用的选项中作出的选择，如体重策略、训练期宏量分配偏好；它是系统计算输入，不是用户手填的营养数值目标 |
| 计算资格 | 在当前信息完整度下，某项建议能否计算；一项不能计算不影响其他功能 |
| 规划证据记录 | 一项规划公式、范围或安全边界所依据的官方文档及精确位置、适用范围、验证状态和版本 |

### 4.2 训练

| 概念 | 含义 |
|---|---|
| 系统训练建议 | 用户主动请求的可编辑候选；采用后作为普通训练计划 |
| 可复用训练计划 | 用户维护的名称、动作、顺序与目标量；可多个并存，不要求绑定日期 |
| 日期安排 | 安排某日时产生的独立计划内容；可多周编排，各周不同；只改某日不影响其他安排 |
| 训练记录草稿 | 批量录入的未提交内容，不是进行中训练，也不进入统计 |
| 实际训练记录 | 某日真实做过的动作及已知数量，可分多条保存，也可完全无计划 |
| 计划项关联 | 实际条目与某日期安排条目的可选稳定对应，不依赖动作名称猜测 |
| 训练日汇总 | 当前有效实际训练、适用消耗及与当天安排的计划量比较 |
| 计划上下文快照 | 记录形成时的必要计划内容及比较依据，后台保存，不是用户维护的版本 |
| 动作定义与指导 | 动作类型、器械、计量方式、示范与要点；按需查看 |
| 运动消耗估算 | 在来源和输入适用时基于实际活动与个人资料得出的近似值 |

界面只称“训练计划”。可复用内容与日期安排是内部独立对象，不重新引入“方案／模板／周期计划”并列入口。

### 4.3 饮食与营养

`docs/product.md` 中的每日营养数值在领域层统一称为“系统每日营养参考”。用户选择饮食策略作为计算输入，不另外创建数值目标；“当前采用值”只指餐食营养结果，不指每日参考。

| 概念 | 含义 |
|---|---|
| 系统每日营养参考 | 系统根据当日有效个人信息、目标和活动上下文计算的热量及营养素参考 |
| 饮食策略 | 用户从系统提供且证据适用的选项中选择的规划方向或范围内偏好；系统据此生成每日营养参考，用户不直接填写结果数值 |
| 餐食记录 | 某次实际进食；可以只含照片、只含手工条目，也可以混合 |
| 食物条目 | 餐食内的一种食物、饮品或组合菜品及其份量和营养值 |
| 营养向量 | 一组按已确定营养项保存的数值及其单位、已知状态和来源 |
| 食物身份 | 不随本次份量变化的食物参考；名称、做法、品牌、来源及基准可区分具体对象 |
| 常用食物 | 用户常用的单项食物，在同一目录前排；常用标记和使用统计不等于独立餐模板 |
| 当日营养汇总 | 当日当前采用值的合计、完整性、系统每日营养参考、剩余量或偏差 |
| 历史趋势 | 按日期汇总已经记录的数据，用于回顾变化；不把缺少记录推断成真实零值或健康结果 |

### 4.4 图片分析

| 概念 | 含义 |
|---|---|
| 餐食照片 | 为分析、重试和用户复核而可靠暂存，并归属某一餐食的临时原始图片；不是长期历史记录 |
| 图片说明 | 用户可选填写的份量、隐藏食材、烹饪方式或实际食用比例说明 |
| 分析任务 | 用户针对一组确定的照片、说明和分析目的明确发起的一次图片估算请求 |
| 分析尝试 | 分析任务的一次具体执行；同一输入失败后的重试产生新尝试而不覆盖旧尝试 |
| 模型原始估算 | 分析执行者返回的候选食物、份量、营养、假设和不确定性原文或结构化结果 |
| 当前采用值 | 当前实际计入餐食和当天统计的营养结果，可以来自自动照片估算、食物数据或用户修正；是后台术语 |
| 结果来源与修正状态 | 后台区分模型估算、食物数据库和用户修正；前台简短标记照片估算，不要求维护审核状态 |

## 5. 个人档案、目标与每日参考

### 5.1 信息使用

- **已确认规则：** 只收集当前建议或计算确实需要的信息；敏感或不适用的信息允许不填。
- **已确认规则：** 某套公式缺少必要输入时，只暂停该项计算并说明缺少什么，不使用虚构默认值；这不阻断计划和记录。
- **已确认规则：** 新建议和当天新计算读取当前个人档案、当前目标与当前策略；历史结果及历史修正读取该结果已经保存的输入快照，而不是用今天的当前值替换过去依据。
- **已确认规则：** 体重、腰围等按实际测量日期／时间保存，录入和修改时间另存。新增不覆盖旧记录；补记旧日期不因录入晚而成为最新测量。当前体重和腰围各自取最近有效测量并显示日期，不能假设同一次都有值。
- **已确认规则：** 修改测量数值或备注保留原实际测量时间，除非用户主动纠正时间；删除测量后重新选择有效当前值。过去参考保留当时依据，新增／补记／删除不自动批量重算过去营养参考或训练消耗。
- **已确认规则：** 首次设置完成状态与计算资格分离：基础资料、初始身体数据、目标方向为必要步骤，提醒可跳过，中途续填，完成后不重复。必需步骤不把腰围等所有扩展字段强制化；未知或不适用的敏感计算输入不使用假值，完成可用资料后保留记录功能。
- **已确认规则：** 体重记录默认提供每周一次的柔性提醒，依据见 E-010、E-015 和 DERV-006；这是可调整的产品默认值，不是适用于所有人的医学处方。用户可以修改周期、暂缓或关闭，忽略提醒不产生惩罚状态。
- **已确认规则：** 超过用户选择的更新周期仍未记录时，依赖体重的当前计算继续采用最近一次有效记录，并同时显示采用值及测量日期；不得静默假设体重没有变化，也不得因资料“过期”阻断训练、饮食和记录功能。
- **已确认规则：** 身高、出生日期等相对稳定档案字段不使用统一周期强制复核；用户在信息实际变化时更新。身体测量提醒与训练提醒、饮食提醒相互独立。
- **已确认规则：** 页面主要展示当前个人档案、当前目标、当前策略和身体测量趋势，不提供通用的“档案第几版”或“目标第几版”浏览。过去使用了什么值由对应建议、每日参考和消耗估算的输入快照解释。
- **已确认规则：** 每套营养或消耗计算方法都要依据官方文档声明适用年龄、生理状态、必要输入和不适用条件；资格不满足或未知时不生成该方法的个性化数值，只保留记录能力、适用的一般人群参考和一般性说明。
- **已确认规则：** 当前能量规划明确区分维持、减重和增重三种体重策略。“增肌”不能自动等同于“体重增加”。没有被当前算法读取的自由文本目标不向用户收集；训练建议需要目标时，使用作用清楚的结构化选项，并说明它只改变本次训练草案。

### 5.2 系统参考和饮食策略

- **继承规则：** 系统根据身体情况和目标提出训练建议与每日营养参考，用户拥有最终选择权。
- **已确认规则：** 系统每日营养参考是可追溯的计算输出，用户不直接篡改该输出。
- **已确认规则：** 系统每日营养参考是饮食汇总唯一的数值比较基准；产品不提供独立的用户手填营养目标，也不允许用任意数值覆盖系统参考。
- **已确认规则：** 用户可以选择系统提供的体重策略和有官方依据的宏量分配偏好。每个选项必须声明证据、适用资格和允许范围；选择变化会生成新的系统参考修订，而不是直接修改某个结果数字。训练目标在生成训练草案时单独选择，不静默改变营养参考。
- **已确认规则：** “增肌期偏高蛋白”只在 E-006、E-007 等证据适用的健康规律运动成人范围内提供，并保持在已登记范围内；“减脂期较低脂肪”只表示依据 E-001、E-002、E-006 和 DERV-005 在适用脂肪范围内选择较低分配，不得降到范围以下，也不能牺牲蛋白质、必需脂肪或总能量约束来制造达标。
- **已确认规则：** 系统参考无法计算时，用户仍可记录餐食和摄入；页面可以显示适用的一般人群参考或相邻范围，但不能要求用户手填一个数字来伪装成系统计划。
- **已确认规则：** 训练建议只有在用户主动采用、编辑或复制后才进入用户训练计划；建议内容作为来源快照保留，训练主页随后只围绕用户计划和实际记录工作。
- **已确认规则：** 系统训练建议保留生成时使用的个人档案、身体测量、目标、策略和规则输入快照及生成时间；相关当前信息变化后，旧建议仍可查看但标记为可能过期，不被伪装成按当前信息新生成的建议。

### 5.3 参考值组成

- **已确认规则：** 系统每日能量与营养目标的准确性优先于餐食识别的准确性和当前实现便利。计算应选择与用户、目标和生理状态相符的可靠依据，并正确处理输入、单位、适用范围和活动重复计算；图片结果的不确定性不能成为降低规划规则质量的理由。
- **已确认规则：** 每日营养参考区分维持能量和目标策略调整，保存各自来源，不把计划训练或当日实际训练作为临时加减项。
- **已确认规则：** 惯常工作、通勤、日常移动和规律训练只在用户确认 PAL 时整体考虑；某一天多练、少练、取消或补做不自动改变当天营养参考。
- **已确认规则：** 蛋白质先独立确定，脂肪保持适用范围，碳水承担满足总能量后的剩余。约束冲突时报告规划不成立，不静默压低某项继续生成伪达标计划。

## 6. 训练领域规则

### 6.1 系统建议与用户计划

- **继承规则：** 用户可以参考、修改或完全忽略系统训练建议，自主安排每周和每天练什么。
- **已确认规则：** 系统训练建议中的频率、强度、组数、次数或周训练量与营养规划数值采用相同证据门槛：必须引用 `docs/domain/calculation-evidence.md` 中达到“可实现”的适用证据，并保留目标、训练经验、可用器械、时间偏好、健康资格和方法版本；没有适用依据或必要输入时只给一般说明，不生成伪精确计划。
- **已确认规则：** 对一般健康中国成人，E-013 只作为总体活动基线：每周 150–300 分钟中等强度或 75–150 分钟高强度有氧运动、每周 2–3 次抗阻训练。它用于检查系统建议是否明显偏离公共健康边界，不变成用户必须完成的任务，也不代替目标特异的抗阻安排。
- **已确认规则：** 对符合 E-014 适用范围的健康成人，抗阻建议从覆盖主要肌群、每周至少 2 天且能够持续的简单安排开始，并按目标形成可修改候选：力量目标可参考约 80% 1RM、每个动作 2–3 组；肌肥大目标可参考每个肌群每周约 10 组；功率目标可参考 30%–70% 1RM 并强调向心阶段快速发力。具体动作、日程和负荷仍按经验、器械、偏好和安全条件调整。
- **已确认规则：** 只有用户已有可靠 1RM 或等效负荷参考时，系统才把百分比换算成具体重量；否则保留相对负荷描述或让用户记录实际可完成重量，不要求为生成计划先做最大重量测试。练到力竭、固定器械类型和复杂周期化不作为普通健康成人默认要求。
- **已确认规则：** 65 岁以上、疾病、伤病、孕期或哺乳期、竞技专项及其他超出 E-013/E-014 适用范围的用户，不套用上述自动参数；仍可手工制定计划、保存专业人员方案和记录实际训练。
- **已确认规则：** 界面统一使用训练计划；用户可从空白、已有计划、实际记录或系统建议建立多个独立计划，不强制绑定日期。
- **已确认规则：** 安排到某日时立即保存独立内容，不延迟到记录时再读取来源。支持多周和各周不同的编排，作为安排日期的深入能力，不要求简单用户维护另一套周期体系。
- **已确认规则：** 修改可复用计划只用于之后复用，不自动改已安排日期；删除它也不删除既有安排或实际记录。来源仅作为后台上下文，不要求维护导入刷新关系。
- **已确认规则：** 修改某日安排只影响该日。改期或取消不移动、删除已发生记录；取消本身不产生消耗或“确定没练”的事实。
- **已确认规则：** 已有实际记录时修改当日安排，当前进度按新安排比较，实际不变；保存处告知进度会更新，旧安排与记录形成时的上下文仍保留。
- **已确认规则：** 系统建议只有主动采用才成为计划，放弃不产生计划；实际记录复制为新计划也必须由用户主动执行。

### 6.2 实际训练记录与计划进度

- **继承规则：** 实际记录默认支持运动后批量填写，不要求实时逐组记录；没有开始、进行中、结束或放弃训练的必经状态机。
- **已确认规则：** 从当天安排、其他计划、上次实际记录或空白创建草稿；仅带出动作和目标量不形成事实。按计划做完时用户可以直接确认整条保存，存在差异则先修改。
- **已确认规则：** 一条记录包含多个动作，整条一次提交；同日可以多条。允许补记、修改和删除，保存失败保留整份草稿，不覆盖其他动作未保存内容。
- **实现约束：** 批量记录的大致时间可明确留空；技术上的创建／结束时间不能代替用户实际运动时间，也不能据此预填运动消耗时长。整条保存以记录标识、版本及规范化内容识别相同重试，陈旧或改内容重试拒绝；修改前保存整条快照及动作修订，删除标记使记录退出事实查询且拒绝旧请求恢复。相关私有字段沿用原表的账号隔离、导出和账号删除边界。
- **已确认规则：** 力量动作支持一行输入组数、每组次数和重量，各组不同再展开；其他类型使用适合的次数、时长或距离。只记得动作时可保存动作，未知量不由计划量补齐，也不补零。
- **已确认规则：** 从日期安排建立的实际条目保留稳定计划项关联；复用上次记录不继承旧日期关联，从其他计划直接记录不自动生成当天安排。独立条目不靠同名自动抵扣，用户无需维护一套跳过／替换状态。
- **已确认规则：** 计划进度按目标量的明确比较单位计算：力量按组数，有氧按所设时长或距离。多指标活动须明确进度采用哪一项，不能隐含合成分数；次数和重量差异作为实际详情，不把组数完成当训练质量达标。
- **已确认规则：** 每项累计同日有效关联实际量，派生未记录、部分记录、达到计划量；只有动作名称或缺少比较目标／实际量时只展示事实，不伪造数量完成率。没有记录不能断言用户没有训练。
- **已确认规则：** 多条实际记录各计一次；超出计划量保留，但不抵扣别的动作，剩余量不为负。不同单位不合成全日百分比。
- **已确认规则：** 修改、删除实际记录重新计算对应日期实际汇总及关联进度，不反向修改计划；更改记录日期时旧日期关联不得继续抵扣新日期安排。
- **已确认规则：** 当天安排改期、删除或删除其中动作后，实际记录与原上下文仍在。失去当前比较目标的条目只作为实际事实；新建的同名动作不能自动承接旧关联。

### 6.3 动作指导

- **继承规则：** 动作指导需要帮助用户理解动作示范与要点。
- **已确认规则：** 用户在查看系统训练草案、训练计划、日期安排和实际记录时都可以打开动作指导，不必先创建实际记录。
- **已确认规则：** 指导内容区分来源、许可、版本和审阅状态；无法确认公开使用许可的内容不能随开源项目直接分发。
- **已确认规则：** 指导可说明常见错误、适用器械和替代动作，但不能宣称对所有人绝对标准或绝对安全。

### 6.4 运动消耗估算

- **继承规则：** 消耗结合个人体重等情况和实际训练内容作近似估算。
- **已确认规则：** 消耗只读取实际动作、时长或训练量；计划和草稿不能记为已消耗，没有必要输入时不生成数值。
- **已确认规则：** 对适用的 18–64 岁健康中国成人，活动能量来源优先使用 T/CSSS 002—2023；未覆盖活动才使用明确适龄的官方或同行评审补充来源，无法找到适用依据时不输出伪精确数字。
- **已确认规则：** 每次估算分别保存总活动消耗和扣除同一时段静息消耗后的净活动消耗；两者都不用于单日营养参考加减，并保留活动分类或 MET 映射、时长、采用体重、公式、证据 ID、版本和限制说明。
- **已确认规则：** 当动作、时长、体重或映射不足以支持合理估算时，估算状态为“无法可靠估算”，不生成消耗数字；训练记录本身仍然有效。
- **已确认规则：** 力量训练、间歇训练和无法准确计时活动只有在动作、强度与时长能够映射到达到“可实现”状态的证据时才估算；无法映射时保留训练量并返回“无法可靠估算”。具体页面可以帮助补充输入，但不能在领域层预置无依据的 MET 或误差范围。

## 7. 饮食领域规则

### 7.1 当前饮食对象

- **继承规则：** 当前饮食由系统每日参考、统一食物目录和实际餐食构成，不建立独立饮食安排或全天记录完成确认。
- **已确认规则：** 旧数据中存在饮食安排或覆盖状态时，迁移不得因此删除历史记录；旧字段不再驱动新界面、提醒或真实全天摄入推断。

### 7.2 食物身份、份量与餐食

- **继承规则：** 拍照与手工选择最终形成同一餐内的单项食物。新餐可先保存日期／时间，照片、餐名、说明或营养明细可以稍后补充。
- **已确认规则：** 一个统一目录支持空查询浏览全部可用食物、整体分类、搜索及常用前排；允许分页，不得仅返回最近记录冒充全库，也不承诺全球食物完整覆盖。
- **已确认规则：** 食物身份与当次份量分开。同一种米饭的不同克数不是两个食物；做法、熟生状态、品牌和来源不同又不能仅凭同名合并。没有可靠匹配时保留可修正的个人条目，不强行合并进公共数据库。
- **已确认规则：** 用户可主动将单项食物设为常用，使用统计也可参与同一列表排序；最近、常用、普通与包装食品不形成并列结果系统。
- **已确认规则：** 选择食物和实际量后生成当餐快照，保留身份、名称、类别、营养来源／版本、基准份量、单位与实际量。改变食物库、常用标记或原餐不自动改历史。
- **已确认规则：** 同一食物份量变化时，所有已知营养按实际量与基准量的比例换算，保持未知项未知；不允许仅改 200 g 为 100 g 而保留 200 g 的营养总值。
- **已确认规则：** 个、碗、杯等单位必须有该食物的基准，毫升与克不能无依据互换。照片份量基准可以是估算，但要保留来源，不能凭单位名猜定值。
- **已确认规则：** 份量修正与食物识别修正不同；更换食物时使用替换食物的基准重新计算。手工营养纠错是异常补偿，不是常规添加默认表单。
- **已确认规则：** 搜不到、分类为空或外部来源失败时保留已选内容，允许补充个人食物；无法确定的营养保持未知，不能从目录缺失推断为零。
- **已确认规则：** 复用昨天鸡蛋和豆浆时只复制所选单项的当前参考及可修改份量，不复制整餐，也不反向修改昨天。模型来源随快照保留，复用不提升可信等级。
- **已确认规则：** 单餐有效结果由互不重叠的食物条目构成，整餐营养为有效条目合计。旧整餐总值与其拆分条目不得双计；不能可靠拆分的旧数据保留独立组合条目，不伪造分项营养。
- **已确认规则：** 公共食物数据必须合法接入并保留来源与许可；已实现的包装食品提供方只是一个来源，不等于统一普通食物库已经交付。

### 7.3 当日营养汇总

- **继承规则：** 只汇总当前有效食物营养，修改或删除时更新对应餐食和日期；已保存的照片估算也计入。
- **已确认规则：** 核心展示为能量、蛋白质、碳水和脂肪的已记录值及系统每日参考。系统可保留参考与记录的差值用于必要详情，但今天不展示剩余，饮食主页不再增加第三组剩余量主信息。
- **已确认规则：** 没有餐食时显示尚未记餐和已记录为零；有餐食但相关营养未算出时为未知／部分合计，不能继续显示成确定零摄入。
- **已确认规则：** 汇总保留来源与处理完整性，前台用必要的整体提示，不逐项堆叠完整性状态。照片估算不能伪装成用户核实或测量值。
- **已确认规则：** 不提供全天覆盖确认；即使所有已保存餐食处理完成，真实全天摄入仍未知。
- **已确认规则：** 膳食纤维、糖、钠等其他来源字段可以继续保存并按需查看，没有适用目标依据时不生成个性化达标结论。

### 7.4 历史回顾

- **继承规则：** 历史按日期索引当前有效训练、餐食和身体测量，并提供记录与趋势两个视角；修改进入原业务编辑器。
- **已确认规则：** 身体趋势读取有效实际测量时间；训练频率标明记录次数或训练记录天数，动作趋势只比较同一具体动作适用指标，不将跨动作总量代表进步。
- **已确认规则：** 饮食只展示逐日已记录值等有数据支持的统计，不输出缺少完整性依据的平均摄入、达标率或连续达标天数。
- **已确认规则：** 缺失日期不补零，后来档案／目标／算法变化不改历史输入快照；用户主动修改历史事实更新该日汇总并保留修订。

## 8. 图片分析与结果采用

### 8.1 照片和任务相互独立

- **已确认规则：** 手机上传后照片先被可靠暂存并关联到餐食；当前主要由应用调用已配置的多模态 API 异步分析，Codex 保留为服务不可用、结果复核或特殊餐食处理时的人工补偿方式。照片本身不是长期餐食记录。
- **已确认规则：** 照片保存成功不等于分析成功；餐食、照片、分析任务和营养结果分别拥有自己的状态。
- **已确认规则：** 一餐可以包含多张照片；一次任务明确使用了哪些照片版本和哪段可选说明。
- **已确认规则：** 原图是临时材料，按既有可配置保留窗口清理，放弃分析、删除照片／餐食／账号时按明确范围提前失效并异步删除；不得依赖已取消的确认采用按钮才能清理。模型原始估算、当前食物与修订不因仅原图删除而丢失。
- **已确认规则：** 自动计入不等于用户已复核；成功或普通单项编辑不隐含用户放弃原图。原图在有效窗口内可用于修正与重试，到期后保留结构化结果并说明无法再用原图识别。本轮不新增保留天数，沿用有效配置。
- **已确认规则：** 用户主动删除照片后，照片不能再用于新分析；已采用的营养记录不能因此悄悄一起消失。
- **已确认规则：** 照片、餐食或账号进入删除流程后，引用它们且尚未完成的分析尝试必须取消或使结果失效；后来到达的外部结果不能恢复已删除对象，也不能进入汇总。
- **已确认规则：** 分析执行者每次只能读取任务明确授权的照片版本和可选说明；任务、照片、餐食、原始结果与当前采用值必须属于同一账号，跨账号读取、关联或回填无效。
- **已确认规则：** 用户完成多模态服务配置并明确授权照片发送范围后，自动分析默认开启；用户能随时关闭并改为手工发起。开关变化只影响后续照片，不自动批量分析历史照片，也不影响照片保存、手工录入或其他功能。

### 8.2 餐食分析、任务与尝试状态

- **已确认规则：** 餐食层不使用一个互斥状态概括全部分析历史，而是分别派生“是否存在可用候选”“是否存在等待中的任务”和“最近一次任务结果”。已有旧候选与最近一次任务失败可以同时成立；从未创建任务时最近一次任务结果为空。
- **已确认规则：** 自动触发或用户手工发起的每次分析请求都创建一个任务。任务引用一组确定的照片、说明和分析目的；照片、说明或分析策略发生变化后再次判断，应创建新任务。
- **已确认规则：** 同一任务可以包含多次执行尝试。因暂时错误对相同输入重试时，在原任务下新增尝试，不创建相同任务，也不覆盖旧尝试。

**已确认规则：** 分析尝试采用以下业务状态：

| 状态 | 含义 | 允许的下一步 |
|---|---|---|
| 等待处理 | 尝试已经创建，尚未开始执行 | 开始处理、取消 |
| 处理中 | 分析执行者正在读取被授权输入并生成结果 | 成功、失败 |
| 已成功 | 本次尝试已经产生模型原始估算 | 查看、采用、修正；输入变化时新建任务 |
| 已失败 | 本次尝试未产生可用结果并保留原因 | 在原任务下重试、手工录入、保持失败 |
| 已取消 | 用户取消尚未完成的尝试 | 在原任务下重试或以新输入创建任务 |

- **已确认规则：** 任务的当前状态由最近一次尝试派生；任务结果、餐食分析状态、旧错误和原始输出都不能覆盖旧尝试。
- **已确认规则：** 分析失败不删除餐食，也不阻止手工录入；原图在有效临时保留窗口内继续用于重试，用户放弃或窗口到期后进入删除流程。
- **已确认规则：** 更换模型 API、切换到本地模型或使用 Codex 人工补偿时沿用同一业务状态和结果边界；供应商名称不是餐食记录和当前采用值的业务身份。

### 8.3 单项结果、自动计入与修正

- **继承规则：** 模型原始估算与当前有效食物记录分别保留；来源、修订和分析尝试属于后台，不要求普通用户管理采用状态。
- **已确认规则：** 识别结果包含可辨认的单项食物／菜品、份量基准和各项营养；混合菜可作为一个条目，不为数据库匹配伪造原料拆分。缺少单项营养时不能把整餐总值复制给每个食物。
- **已确认规则：** 餐食尚无已有录入或修正内容时，成功结果自动形成食物条目并计入汇总，无必经确认按钮；界面短标记“照片估算”。
- **已确认规则：** 已有手工、修正或其他有效结果时，后来分析保留为候选，不静默覆盖；用户明确使用新结果时预览替换范围，原有效值在替换成功前继续生效。
- **已确认规则：** 份量修改按基准重算，替换错误食物后按新基准计算，漏项可补、多余项可移除。以上修改只影响当前餐食，保留旧值和来源。
- **实现约束：** 单项目录替换由服务端解析账号可用食物及指定版本，按新基准/单位重算并保存独立快照；保留原条目身份与分析关联，当前营养来源改为所选食物，旧估算进入修订历史。餐食及条目修订号在同一事务校验，只更新目标项和餐食修订；陈旧重试返回冲突，不追加食物或覆盖后续修改，无需新增表或迁移。
- **已确认规则：** 对同餐多图、重试和重新识别统一校验覆盖范围；替换的旧条目退出当前汇总，未覆盖条目保留，同一内容不与整餐总量双计。旧任务的迟到结果不能覆盖新结果或人工修改。
- **实现约束：** 完整结果替换绑定餐食和结果修订号，旧值、来源及替换前快照在同一事务保存；同一操作编号的相同重试不重复计入，改变范围或过期修订拒绝。撤销只在餐食自替换后未再变化时恢复替换前内容；撤销后新的明确预览可再次使用结果，旧操作编号不可重用。原图过期不影响已保存结果的查看、替换或撤销。
- **已确认规则：** 图片份量默认是可见盛取量，实际食用比例未知时保留假设；用户说明未吃完时应使用实际食用量估算，不能声称照片能直接测量真实摄入。
- **已确认规则：** 原始结果保留供应商／模型、营养来源、版本、假设、可用不确定性与任务输入；复用食物时保留估算属性。
- **已确认规则：** 分析失败、原图到期或没有有效营养时餐食仍在，营养保持未知；用户可以手动补充，不强制处理或制造待办配额。

## 9. 训练与饮食的并列展示

- **已确认规则：** 今天只展示已记录四项营养与训练摘要。饮食上一餐时间／名称组合进入饮食页，拍照与记录训练使用各自唯一业务流程。
- **已确认规则：** 有当天安排时训练摘要显示计划量的完成、部分与尚未完成记录；无安排时显示实际内容。未安排的可复用计划不进入今日任务。
- **已确认规则：** 系统每日参考由当日有效档案、目标、策略和惯常活动生成，不因当日实际训练多做、少做、取消或补做而改变。
- **已确认规则：** 图片估算只影响已记录摄入，不影响营养规划公式和资格。运动消耗不作为需要“挣取”的进食配额。
- **已确认规则：** 更新记录只更新相应事实及汇总，不反向改另一模块的目标或记录。

## 10. 提醒与跨页草稿

### 10.1 提醒

- **继承规则：** 训练、饮食、身体测量各自配置开关与时间／周期，互不依赖。
- **已确认规则：** 训练按当天有安排和用户设置时间提醒，不判断“是否开始”；饮食做简单记餐提醒，不推断漏记、全天完整或剩余营养。
- **已确认规则：** 身体提醒按测量周期，允许调整、暂缓和关闭；具体默认周期依据保持原证据。忽略提醒不改变任何事实或产生惩罚状态。
- **已确认规则：** 提醒设置放入我的低频设置，图片识别开关归饮食；通知权限只在需要时申请，拒绝不影响记录。

### 10.2 日期、草稿与提交

- **已确认规则：** 记录默认入口日期：今天入口为今天，业务历史日期入口保留所查看日期。历史修改保存／取消后恢复原日期、筛选与位置。
- **已确认规则：** 页面切换保留草稿，保存失败或同账号重新登录后可继续；草稿不计入记录和统计，不以后台查询结果覆盖用户未提交输入。
- **已确认规则：** 同一次保存重试使用同一逻辑提交身份，只产生一条事实；并发修改以明确冲突处理，不静默覆盖。整条训练保存不能只成功一部分却对用户声称全部成功。
- **已确认规则：** 跨午夜更新今天视图，不改变已建立草稿日期。用户主动改日期后只归属一个自然日，重新汇总受影响日期。
- **已确认规则：** 草稿按账号隔离，不能在账号切换后显示给其他人。持久化方式、清理和失效策略由工程验收明确，本规则不授权在日志、反馈或不受控长期本地存储保存健康明细。

## 11. 计算与营养数据规则

### 11.1 每日营养参考

- **已确认规则：** 输入至少区分计算当时的当前个人档案、相应身体测量、目标、策略、基础活动、计划训练和实际训练，并把实际使用值保存到结果快照；具体公式只使用官方文档明确要求的输入。
- **已确认规则：** 输出区分能量和各营养素，保留单位、适用人群、方法版本、证据 ID、来源与限制。
- **已确认规则：** 每套正式采用的规划算法必须能够用公开依据、公式测试样例和边界样例复核；来源选择、公式转写、单位换算、舍入、活动去重和版本应用错误都属于规划计算缺陷，不能用“结果只是估算”免责。
- **继承规则：** 参考值属于一般健康与健身辅助估算，不是处方；个人实际需要可能高于或低于结果。
- **已确认规则：** 中国一般成人的基础能量和宏量营养基线优先采用中国营养学会 2023 DRIs；国家卫健委现行指南用于其明确覆盖的体重管理人群。National Academies 2023 EER、NIDDK 动态体重模型和国际专业组织正式立场用于补足与交叉核验，不与中国参考静默取平均。
- **已确认规则：** PAL 候选必须根据用户的惯常职业活动、日常移动和规律训练整体判断，并对照 E-004 第 7 章表 7-1 的活动模式；不能仅凭是否达到健康运动建议、单一日步数或一次训练直接确定 PAL。
- **已确认规则：** PAL 结构化输入分为三组：惯常工作或学习时的坐、站、移动和体力劳动模式；日常生活中通常发生的步行、家务和通勤；每周反复出现的训练或高强度休闲活动及其频率、时长和强度。三组输入分别保存，系统匹配 E-004 表 7-1 及第 148–149 页描述时必须去除同一活动的重复计入，不把某个单项直接换算成 PAL 分数。
- **已确认规则：** 当前没有官方认可的简便工具能够准确分类个人 PAL。活动资料清楚时系统可以提出可修改的候选档位；资料同时符合相邻档位或明显不完整时，展示相邻方程形成的参考范围，不伪造单一精确值，也不阻断训练与饮食记录。
- **已确认规则：** 输入不足以形成候选时不输出单一的个体 EER；可以展示中国 DRIs 对应人群参考和相邻 PAL 方程范围，并明确还缺少哪些输入。用户不补充仍可正常使用训练、饮食和体重记录。
- **已确认规则：** 初始 EER 必须显示采用的 PAL 候选及相邻档位差异。体重记录用于显示随时间的实际方向，并作为用户以后调整目标的依据；当前规则不设没有官方直接依据的统一观察天数、波动容差或自动调整步长，系统不得自动改写当前目标或历史。未来若引入自动校准，必须另行登记官方依据、适用范围和验证样例。
- **已确认规则：** 维持体重时周目标策略调整为零。减脂时只有在官方指南适用资格内才能采用其目标速度、能量缺口和安全边界，并默认从官方范围的保守端开始；长期体重变化使用动态模型，不用固定能量密度直接线性外推。
- **已确认规则：** 当前没有同等级官方依据能够保证能量盈余转化为肌肉；增重规划必须把总体重路径与增肌目标分开，不承诺增加部分均为肌肉，也不生成全体用户通用的固定盈余默认值。
- **已确认规则：** 18 岁及以上、非孕期或哺乳期且不处于需要医疗处理状态的一般成人，只有在用户给出目标体重和目标期限后，才可用 E-005 的完整动态模型生成总体重路径与相应能量计划；实现前必须完成独立复算和许可审查。没有目标期限或无法使用完整模型时，只显示维持参考与正能量平衡原则，不用固定常数补位。
- **已确认规则：** BMI 低于 18.5 的用户先显示 E-010 的“排除疾病原因并逐渐增加至推荐水平或稍高”边界；在用户确认已完成适当评估前，不自动生成个性化增重能量目标。BMI 不能替代体成分或医学判断。
- **已确认规则：** 无规律训练时蛋白质采用中国 DRIs 对应人群参考；健康规律运动成人的范围必须来自正式专业组织文件。普通阻力训练的约 1.6 g/kg/日仅作为位于 1.4–2.0 g/kg/日正式建议范围内、并由系统综述交叉支持的产品参考中心，不表述成确定阈值。
- **已确认规则：** 蛋白质使用何种计算体重必须有适用人群的直接依据。肥胖、明显低体重或特殊体成分时，不无条件用实际体重相乘；依据未完成时停止自动输出该个性化蛋白质目标。
- **已确认规则：** 对中国成人 BMI 低于 18.5、达到 28.0 及以上，或用户声明存在显著特殊体成分、疾病、孕期或哺乳期时，不自动套用健康运动成人的 `g/kg 实际体重`目标，也不借用住院或疾病人群的理想体重、调整体重公式。系统仍可显示 E-001 对应年龄和性别的一般人群固定参考量，但不让用户手填数字冒充系统个性化规划。
- **已确认规则：** 脂肪使用适用官方范围，单点值若取范围中点必须标记为产品分配规则；在蛋白质与脂肪约束满足后，碳水承担剩余能量和主要训练日能量变化。三者无法与总能量同时成立时，返回约束冲突并修正目标策略。
- **已确认规则：** 当前范围不把 PAL、体重趋势、特殊体重蛋白质或增重盈余中缺少官方依据的数值做成隐藏默认值；上述项目分别采用“候选或范围 + 用户确认”“不自动校准”“停止运动蛋白质自动计算”和“目标体重 + 期限的完整动态模型”处理。

### 11.2 运动消耗

- **已确认规则：** 使用有证据记录的活动分类或 MET、实际时长和当日有效体重形成近似估算，并说明标准化数据不等于个人测量。
- **已确认规则：** 不具备合格来源或必要输入时不输出消耗数字，不能用默认值伪装精确。
- **已确认规则：** 当前自动估算范围只包含能被 T/CSSS 002—2023 或其他达到“可实现”状态的直接来源可靠映射的活动。无法确定活动、强度或时长时保留训练事实并显示“无法可靠估算”；以后扩展来源不构成当前规则中的隐藏待定默认值。

### 11.3 食物营养

- **已确认规则：** 每条食物营养数据都要说明每 100 克、每份或用户输入份量的换算基准。
- **已确认规则：** 同名食物的地区、品牌、烹饪方式和数据类型可能不同；匹配结果需要可修正。
- **已确认规则：** 图片分析可以直接给出候选营养值，也可以先识别食物与份量再匹配营养数据源；无论采用哪条路径，都要保留各项结果的来源、版本和假设。
- **已确认规则：** 食物营养来源按具体性排序：用户录入或拍摄的当前产品营养标签；能够合法使用的 E-011 中国常见食物数据；其他已核验且许可兼容的数据；模型直接估算。更具体来源只替换它明确覆盖的贡献项，不能静默覆盖整餐。
- **已确认规则：** 预包装食品按标签所示的每 100 克、每 100 毫升或每份基准换算，并保留品牌、产品名称、标签版本或拍摄时间和实际食用量。执行时使用该日期有效的标签标准版本；E-012 的字段和单位可作为最新发布规则核对来源。
- **已确认规则：** 食堂混合菜无法可靠拆分时允许保存为“整道混合菜候选”，同时保留可见食材、烹饪方式、盛取量和隐藏油盐等假设；不能为了匹配数据库而伪造各食材克数。用户以后可以修改该菜品或拆成互不重叠的条目，不能保留同范围整菜总量重复计入。
- **已确认规则：** E-011 平台数据有明确版权声明。未取得批量使用和再分发许可前，只能作为来源核对和合法查询候选，不能把整库复制到公开仓库；若运行时也无法合法访问，则保留手工、包装标签和模型候选路径，不以内置盗版数据补位。

### 11.4 规划证据与算法验收

- **已确认规则：** 规划证据统一登记在 `docs/domain/calculation-evidence.md`；正式算法中的每个外部常数或范围必须引用一个已核验记录，产品推导同时引用全部输入记录。
- **已确认规则：** 只有证据状态为“可实现”的规则才能进入自动规划核心；“待取得原文”“待核对精确位置”或“只作补充”的资料不能单独支撑生产数值。
- **已确认规则：** 正式算法必须通过官方样例或独立复算、输入资格、单位与舍入、活动去重、周预算守恒、宏量能量守恒、结果可重现和边界场景八类验证。

## 12. 关键状态与冲突处理

本表索引前文规则，不建立第二套状态机。

| 场景 | 当前规则 |
|---|---|
| 看计划但没有保存实际记录 | 不产生训练事实或消耗 |
| 按计划运动后整条保存 | 用户确认的内容成为实际事实，并更新有关联的进度 |
| 计划 3 组，只记录 2 组 | 部分记录，不因动作同名判为完成 |
| 同天分两条记录同一计划项 | 各条实际量累计一次；超出不抵扣其他动作 |
| 修改可复用计划 | 不影响已安排日期和历史实际 |
| 修改当天安排 | 更新当天比较目标，实际不变，保留旧依据 |
| 改期或取消安排 | 不移动或删除实际记录 |
| 图像识别成功且没有已有内容 | 保存单项结果并计入，标记照片估算 |
| 已经手工修改后模型迟到 | 保存候选，不自动覆盖 |
| 图片任务入队失败／执行中断 | 状态必须可恢复或明确失败，不能永久等待且承诺原图可用 |
| 修正食物份量 | 同步换算该项营养，未知项不补零 |
| 更换食物或重新识别 | 明确替换范围，同餐不双计 |
| 补记旧体重 | 按实际日期归属，不因录入晚成为最新值 |
| 修改历史餐食／训练 | 更新该日事实及汇总，保留当时计算依据 |
| 多端冲突／网络重试 | 保留输入、校验版本和去重，不静默丢数据 |
| 删除餐食后模型返回 | 不恢复对象，不计入营养 |
| 多用户使用 | 记录、照片、任务、常用和草稿按账号隔离 |

## 13. 数据控制与多用户边界

- **继承规则：** 用户能够查看、导出、备份或删除自己的长期业务记录；部署和重启不能导致长期业务数据或仍在有效处理期内的临时照片意外消失。
- **继承规则：** 朋友阶段每个账号的数据默认相互隔离，不能访问他人的档案、训练、饮食或临时照片。
- **已确认规则：** 导出应包括用户原始记录、当前采用值、必要来源和时间信息；具体文件格式后移到技术设计。
- **已确认规则：** 长期导出和备份默认不包含原始照片；可以导出照片生命周期、分析任务和采用值的关联元数据。原图已经删除时仍须完整导出其余记录，不能把删除后的临时材料表述为数据缺失事故。
- **已确认规则：** 删除操作必须具有明确范围及影响集合，例如仅照片、单餐、某次训练或整个账号；删除前必须说明会从当前汇总排除什么、会取消哪些未完成任务、哪些已采用营养结果由用户选择保留或一并删除。确认方式和恢复机制后移到 Phase 3 与 Phase 4。
- **已确认规则：** 动作定义、获许可的动作内容和公共营养参考数据可以作为共享只读参考；用户计划、个人常用食物、餐食、临时照片、分析任务和采用值均为账号私有。主动公开或分享属于未来独立能力。
- **继承规则：** 照片、数据库、备份、凭证和用户记录属于私有运行数据，不进入公开 Git 仓库。

## 14. 健康、安全与内容边界

- **继承规则：** 产品只提供一般健身和营养辅助，不诊断疾病、不治疗、不替代医生或注册营养专业人员。
- **已确认规则：** 对缺少关键输入、特殊生理状态、伤病或明显超出规则适用范围的情况，系统应降低结论强度或不生成个性化数值，而不是猜测。
- **已确认规则：** 动作示范说明“如何理解和执行”，不能承诺某动作对所有用户安全；内容应允许提供限制条件和替代动作。
- **继承规则：** 系统每日营养参考、运动消耗和图片营养结果统一标为估算；“估算”不降低规划算法必须正确实现官方依据的要求。
- **已确认规则：** 系统每日营养参考和运动消耗同时保留官方证据记录、版本、适用范围、产品推导和不确定性；图片营养结果另行保留模型、营养来源、假设和不确定性。
- **已确认规则：** 不利用提醒、连续记录或超标文案制造羞耻、惩罚或医疗恐慌。
- **已确认规则：** 第三方动作视频、营养数据库和其他内容只有在许可允许时才能随开源版本分发；链接引用与内容再分发需要分别判断。

## 15. 确认沿革与一致性

- Phase 2（2026-08-23）确认的官方证据门槛、规划资格、宏量计算顺序、历史快照、账号隔离和私有数据边界继续有效；数值规则仍由本文相关章节及 calculation-evidence 登记维护。
- Phase 6.6（2026-09-05）讨论确认的今天摘要、统一食物选择、单项照片、批量实际训练、独立日期安排、我的与跨页规则，替代此前冲突的实时训练、饮食安排、全天覆盖确认和重复设置流程。
- 计划与实际分离、营养参考与实际摄入分离、来源与历史不被后来状态覆盖，仍是共同不变量。
- 新规则待按交付清单实施和验证；旧测试通过不构成新数据契约、迁移或界面流程已经交付的证据。

## 16. 实现前与迁移边界

- 稳定食物身份、份量基准、单项识别结果、批量训练保存、日期安排副本和首次设置完成状态需要实际数据/API 支持，不能仅改名称。
- 原有计划、周期安排、已完成与未完成的旧训练数据、整餐估算和审计记录不得因删去旧界面而直接清除。不能证明实际已发生的旧计划量不迁移成实际事实。
- 旧整餐营养无法可靠分项时保留组合记录，可由用户以后修正；同一来源的旧总量与新条目不能双计。
- 本轮不执行 migration。未来变更必须先通过隔离测试库前向升级、已有记录可读和跨账号验证，生产迁移按授权范围另行处理。
