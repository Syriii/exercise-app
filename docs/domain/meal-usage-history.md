# 餐食照片与使用过程留存

## 范围

用户确认照片和识别后的调整过程都应保留，供后续优化。此处是账号私有业务记录，不是自动上传的诊断日志，也不是已审核的训练集。界面不增加打卡、填写修改原因或结束记录等必经操作。

- 照片保存实际上传版本，保留哈希、MIME、大小及餐食关联；上传前压缩后的文件才是识别依据，不声称保存了手机原始照片。
- `temporary_media.expires_at = null` 表示长期保留；导出文件仍有限期。旧可用餐食照片只调整保留元数据，不恢复已删除文件、不取消进行中的删除。
- 每次尝试记录请求模型和提示词版本；成功时保存结构化原始结果、提供方返回的模型、用量、耗时等可用证据。未知用量保持空，失败保留状态、错误码与起止时间，不留未校验的任意响应或错误正文。
- `previous_analysis_id` 显式关联重新识别的前一次结果；新识别不会覆盖旧结果、已有手工食物或用户修正。
- `meal_record_events` 按递增ID保存餐食、食物、分析、尝试及照片生命周期已落库的变化前后快照。事件与业务变更同事务，回滚时一起回滚；并发冲突和去重命中的请求不制造一次成功修改。替换/撤销关联其原有操作ID和快照。
- 不反推操作意图：补录可能是漏识别，也可能是后来又吃了；删除可能是误识别，也可能没有吃；无修改不代表复核；修正值不代表称量或营养测量真值。

## 使用与删除

餐食照片详情折叠提供查看、下载、删除；仅本人登录可访问，响应禁止缓存，对象路径不出接口。删除共享原图后该照片的各次识别都不可再用图，进行中结果失效；结构化结果及修改过程不因此被删除。删除餐食后照片进入清理，删除账号按既有范围级联清理。删除失败保留待清理状态，后续清理重试。

JSON账号导出包含过程、尝试、原始结果、当前食物及照片关联元数据，不包含图片字节；照片可以在餐食内下载。业务事件不进入公共日志、问题报告、管理员健康数据面板或代码仓库。RLS同时隔离事件归属与餐食归属，账号删除级联删除历史。

存储上限继续保护服务器：空间不足时拒绝新上传并提示下载、删除或扩容，不自动淘汰旧照片。长期保留不等于备份；当前数据库备份不含媒体volume，异机照片备份是单独的部署事项。

## 数据边界

只记录功能上线后的真实操作，不为旧数据合成完整历史。原有修订和模型结果仍可回溯，已清理照片无法恢复。历史按事件ID还原，当前餐食有效条目才计入营养汇总。

后续优化先在用户授权范围分析修改分布；需要用保存照片再次调用模型时另行确认样本及调用预算。留存本身不新增模型调用、不授予跨账号读取权、不自动对外训练或共享。
