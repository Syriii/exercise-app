# 图片识别实拍评测

识别结果是可修改的估算，不能用模型请求成功率代替食物、份量或营养准确性。此工具不连接业务数据库，不读取用户照片，不改变饮食记录。

## 数据与授权

首批参考 [Google Research Nutrition5k](https://github.com/google-research-datasets/Nutrition5k)：公开实拍餐盘、称量食材及按营养数据库计算的标注，许可 CC-BY-4.0（Google Research / Thames 等，CVPR 2021）。不是实验室测得的整餐营养，也不代表所有中式餐食。

中餐试点可使用 [Meituan DiningBench](https://huggingface.co/datasets/meituan/DiningBench)（CC-BY-NC-ND-4.0）原始图片和标注，仅在非商业内部评测中使用。选取用户实拍图，不用商家展示图。它主要是餐馆菜品，不能当作中式食堂的代表性样本；部分营养真值来自商户标签，其他部分由模型结合菜谱与份量估算后人工核对，[论文方法](https://arxiv.org/html/2604.10425v1)未逐样本标记来源，因此仅作有噪声的对照，不充当称重真值。图片包约 8GB，准备脚本流式提取固定的 20 张中式主食图片，跳过扩展名与实际编码不一致的文件，清单记录官方修订号、来源路径与 SHA256。若要判断食堂份量与营养是否可用，仍需另有获授权且称重的实际食堂样本。

`apps/server/scripts/prepare-photo-evaluation.mjs` 从官方 depth test split 中筛选 100–1000g、能量大于 0 的餐盘，按固定种子 `exercise-photo-eval-v1` 排序取 20 张。先固定样本再预测，不按识别结果剔除失败样本。清单保留来源、图片/元数据 SHA256 和真实标注；照片、清单和逐项结果只存私有临时目录，不提交 Git。

准备下载不调用模型。发送照片前必须获得所用样本、服务与调用数量的明确授权；程序要求 `PHOTO_EVALUATION_APPROVED=true` 及精确清单摘要。一次清单最多 30 张，每张仅一次调用，关闭自动重试。生产媒体与账号数据不用于此工具。

每次提供方请求（包括内部重试和失败）随分析尝试证据保存配置模型、返回模型、请求 ID、状态、请求时间、耗时、输入/输出/总 token 与缓存命中/未命中 token。DeepSeek 返回用量时依 [官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/) 的北京时间峰谷价估算人民币费用，连同费率快照版本、价格来源及命中/未命中价保存；缺少缓存拆分时给上下界，缺少输入/输出 token 或未知模型时费用为未知，不填 0 或声称与账单一致。评测 JSONL 逐图保存调用证据，并在汇总中单列已估价、未知次数和费用区间。`estimatedCostCny.knownSubtotal` 仅汇总已估价请求；有未知费用请求时，`minimum` 只是该已知小计给出的整批费用下界，`maximum` 为 `null`，不能把已知小计当成总费用或上限。所有费用均未知时，已知小计为 0 表示没有可计价部分，不代表调用免费。

因照片删除或超时恢复而已经结束的尝试，晚到响应只向原尝试补记调用证据，不恢复餐食、不改变原来的失败原因和结束时间，也不影响新尝试。同一调用重复交付不重复追加；已删除的分析或账号不重建记录。

正式 Worker 沿用原分析尝试的 `evidence`：发送前保存 `preparedCalls`，响应或失败后独立保存累计 `calls`，成功保存后才允许瞬时故障重试或写餐食结果。通过本地生成的 `callId` 关联两种记录，不增加新表；准备或响应保存失败会停止后续模型请求。中断后只有准备记录的调用仍是未知，不能据此认定未发送、已收费或费用为零；已有调用证据继续按账号隔离、导出和主动删除规则保留。

价格快照于2026-10-28重新核对官方页面，Flash峰谷单价未变；旧视觉模型名当前由DeepSeek-V4.1-Flash-1017承接。每个新调用保存当时快照，历史证据不重算。官方峰值窗口排除中国法定节假日；应用尚未维护经核实的提供方节假日日历，因此北京时间工作日9:00–12:00、14:00–18:00内记`peak_or_off_peak`和`public_holiday_unverified`，费用下界按空闲价、上界按高峰价；三项单价字段保存上界，`minimumRates`保存下界。窗口外和周末按空闲价；缓存拆分未知时，在时段区间上继续保留缓存区间，不把两种不确定性压成精确金额。

## 执行

1. `node apps/server/scripts/prepare-photo-evaluation.mjs /绝对路径/私有评测目录`，检查真实照片和清单、记录 SHA256。
2. 构建服务端。授权后使用既有只读 secret 文件配置 `DEEPSEEK_API_KEY_FILE`，沿用实际 `DEEPSEEK_BASE_URL` / `DEEPSEEK_VISION_MODEL`；不要在命令行写入密钥原文。
3. `node apps/server/dist/entrypoints/evaluate-photos.js /绝对路径/manifest.json 已批准的SHA256 /绝对路径/新结果.jsonl`。环境授权开关必须在得到同意后设置，不代表工具自行取得了授权。
4. 保留样本意图、逐物理请求准备与完成记录、结果、失败、用量及模型/提示词版本。不自动覆盖旧文件或重跑结果不明的付费请求。中途退出时先核对调用证据，再决定是否需要额外授权。

每个样本原有的 `request_started` 表示进入分析流程。每次物理请求在网络发送前，先写 `provider_request_prepared` 并 `fsync`，记录本地生成的 `callId`、意图时间 `preparedAt`、配置模型和 `dispatchState: unconfirmed`；只有该记录持久化成功才允许发送。准备写入的等待上限为5秒，并受本次分析剩余总时限约束。`preparedAt` 不等于真实请求时间；若准备期间跨越峰谷边界，费用按真正开始发送时记录的 `call.startedAt` 估算，两者只通过 `callId` 关联。

每次响应或失败后，立即写 `provider_calls_recorded` 并 `fsync`，保存最新 `callId` 与该样本累计的 `calls`，完成写入另有最多5秒等待窗口，随后才返回结果。写入或同步拒绝，以及准备/完成保存等待超时（`deepseek_call_preparation_failed` / `deepseek_call_recording_failed`），都会终止整批；即使底层I/O仍挂起、尚未设置本地失败标记，也不能继续下一张或自动重发。等待上限不表示底层文件操作已经取消。`prediction.calls` 保留同一份最终调用快照；汇总只取每个样本最终返回或失败中的调用一次，不能把累计日志、重复交付和 `prediction` 再相加。

准备记录只证明保存了发送意图，不证明请求已经发出、被提供方接收或产生费用。进程可能在准备之后、发送之前或响应完成记录持久化之前退出；同一样本中没有完成快照可匹配的 `callId` 必须保留为状态和费用未知，不补零，也不自动重跑。只读辅助函数 `unresolvedEvaluationProviderRequests` 按样本与 `callId` 对完整日志行去重匹配，并核对配置模型、有效请求时间、有限非负耗时及终结状态；用量与费用允许明确为 `null`，缺字段或错配片段仍保留未知，不依赖日志数组顺序。截断的末行不能当作完成证据。若调用完成记录已经持久化而 `prediction` 尚未写入，用量证据仍可核对，但识别结果未完成，不能据此重新发起付费请求。

中断后可执行 `node apps/server/dist/entrypoints/inspect-photo-evaluation.js /绝对路径/既有结果.jsonl`。此入口无需模型密钥或调用授权开关，只读取指定文件并向标准输出打印核对报告，不联网、不写回、不重发、不按当前价格重估。输入 SHA256 和字节数用于对应原始证据。完成调用按样本与 `callId` 去重；旧日志按样本内序号及请求身份匹配。累计完成记录与 `prediction.calls` 不重复相加，冲突快照不进入已知费用小计。

报告分别列出已记录完成调用、未终结意图、缺失预测、损坏/截断行号和历史费用小计；不输出原始坏行、图片、预测candidate或额外未知字段。元数据的预期样本尚未出现记录时，`unobservedSampleCount` 表示评测不完整，不代表额外模型请求或费用。未知、冲突或不完整证据不能给出可信整批费用上限，`estimatedCostCny.maximum` 保留 `null`；已完整记录调用但缺预测时仍能核对其既有费用，识别结果继续标未完成。报告的 `manualReviewRequired` 提示人工核对，不能作为追加调用许可。

图片是模型唯一的样本输入；真实食材、称量、营养和样本 ID 不进入提示词。使用应用同一识别适配器与提示词，不为评测偷偷提供答案。

## 指标和人工复核

- 请求成功/失败单列；每个指标分别报告可评分数量与未知数量。失败和未知不能按 0 营养处理。
- 能量、蛋白质、碳水、脂肪以及可换算的总克重：平均绝对误差 MAE；归一化绝对误差为 `100 × 绝对误差总和 / 对应真实值总和`，不是逐餐百分比的平均。分母为 0 时保留未知。
- 只有所有识别项的份量均明确为克，才计算整餐克重；“个/碗”等不擅自换成克。必须披露可评分覆盖率，避免仅评价少量容易样本。
- 人工逐图核对主要可见食物，记录漏项、误识别、合并/拆分与不确定项。配方里的油盐和藏在混合菜内的食材不直接当成可见漏项；不能从营养误差倒推出识别召回率。
- 初次评测报告测量值、典型错误和适用限制，不擅自宣称达到医学精度。美国食堂公开集只能提供起点；大陆食堂、包子/夹馍/豆浆、混合炒菜仍需有授权且具真实标注的本地样本补充。

## 同样本提示词对比

新版候选先固定提示词版本，再对同一清单各请求一次；不得给模型传入旧预测、标签或营养答案。旧结果只用于离线比较，保留新结果的完整candidate（含份量note、assumptions、confidence与uncertaintyNote），不只保留总营养。

`compareEvaluations`要求两轮样本ID集合和真值完全一致，按ID配对而非按结果顺序。每个指标同时列出两轮整体覆盖、共同可评分样本误差、新增可评分和丢失可评分数量；失败和未知不补零。覆盖减少不能被解释为准确率提升，可评分质量增加也不等于估量更准。

同一已见样本集是开发回归，不是独立测试集，不能据此宣称日常餐盘整体精度达标。发布前需要请求成功/营养覆盖不退步、共同样本能量误差改善，并结合宏量误差及逐图可见食物复核判断是否存在明显回退；未证明改善则保留当前线上提示词，不擅自追加调用。

## 中断恢复专项

恢复测试与真实识别效果是独立门禁。假模型测试和真实隔离 PostgreSQL 的子进程强杀验证覆盖：过期失败、事务回滚、跨账号隔离、并发回收/重试、旧尝试迟到写回、照片过期与只产生一次当前贡献。它们不能作为实拍准确性证据。最新实测与发布状态在当前任务计划维护，不将工具存在写成评测已完成。
