## 1. 全 App 逻辑链

```text
打开 App
├─ 未登录 → 登录／注册
│  └─ 预置密码账号 → 首次改密
├─ 首次设置未完成 → 接着完成必要步骤
└─ 日常使用
   ├─ 今天 → 看摘要，快速进入记餐／记训练
   ├─ 饮食 → 记录吃了什么，查看当日营养
   ├─ 训练 → 看／改计划，记录实际练了什么
   ├─ 历史 → 回看记录和趋势，进入原记录改错
   └─ 我的 → 身体数据、资料目标、低频设置
```

五个一级入口在手机上使用底部导航。今天只分流，不建立另一套记录表单；历史只索引，不建立另一套编辑器。所有跳转携带日期、记录和返回位置。

## 2. 登录与首次设置

```text
登录成功
├─ 首次设置已完成
│  └─ 返回原目标页面；没有目标时进入今天
└─ 首次设置未完成
   ├─ 基础资料【必要步骤】
   │  ├─ 填写必要的基本信息与活动情况
   │  └─ 已填内容保留，允许返回修改
   ├─ 身体资料【必要步骤】
   │  ├─ 建立初始身体测量
   │  └─ 腰围、备注等附加字段按需填写
   ├─ 目标方向【必要步骤】
   │  ├─ 选择体重方向
   │  └─ 目标体重／期限等仅在适用时显示
   └─ 提醒【选填】
      ├─ 选择开启并设置时间／周期
      └─ 跳过 → 进入今天
```

前三步不能整体“以后再设置”；中途离开后恢复到未完成步骤。必需步骤不代表所有扩展字段强制填写。无法提供敏感或不适用的计算输入时，记录其未知状态并停止相应计算，不能要求虚构答案才能进入 App。

完成后不再显示“按步骤检查”；资料修改从我的进入。已有用户使用原有有效数据衔接完成状态，不因导航改造重新填表。体重方向与生成训练计划时的训练目标分开表达，不能把“增肌”自动解释为“增重”。

## 3. 今天：两张摘要卡

```text
进入今天
├─ 饮食卡
│  ├─ 今天已记录：能量、蛋白质、碳水、脂肪
│  ├─ 拍照记一餐【主动作】→ 饮食的同一拍照流程
│  └─ 上一餐：时间＋名称【整行可点击】
│     ├─ 有餐食 → 当天餐食列表
│     └─ 无餐食 → 显示尚未记餐，可进入饮食页
├─ 训练卡
│  ├─ 今天有安排
│  │  ├─ 计划名称／摘要
│  │  └─ 按计划量记录的完成和剩余摘要
│  ├─ 今天没有安排
│  │  └─ 显示已记录训练内容；无记录时简单说明
│  └─ 记录训练【主动作】→ 训练的同一记录流程
└─ 身体测量到期【仅到期出现轻提示】
   ├─ 记录测量 → 我的／身体数据
   └─ 暂缓或忽略 → 正常使用
```

- 不显示饮食剩余量，不增加“查看饮食详情”重复链接，不堆计划管理和长表单。
- 食物识别尚未完成时，用餐食状态和必要的简短提示解释部分合计，不把未知计为零。
- 训练“完成”明确指计划量的记录进度，不评价效果；存在部分记录时摘要须能表达，不只显示一个笼统百分比。
- 今天页的过期测量提醒不变成第三张常驻大卡；训练、饮食提醒不占据三套首页提醒卡片。

## 4. 饮食：记餐与查看当天记录

### 4.1 页面主干

```text
进入饮食
├─ 日期【默认今天；保留入口携带的历史日期】
├─ 当日概况
│  ├─ 已记录能量、蛋白质、碳水、脂肪
│  └─ 对应每日参考；无法计算时说明参考暂不可用
├─ 记录入口
│  ├─ 拍照记一餐
│  └─ 添加食物
├─ 当天餐食【按时间】
│  ├─ 时间／餐名、食物摘要、营养摘要
│  ├─ 打开餐食
│  │  ├─ 修改日期、时间、名称、说明
│  │  ├─ 修改食物和份量
│  │  ├─ 补充漏项或移除多余项
│  │  └─ 保存 → 更新该餐与日期汇总
│  └─ 删除餐食 → 说明范围并确认
└─ 拍照识别设置【次要入口】
   ├─ 照片发送说明与授权
   └─ 拍照后自动识别开关
```

没有记录时展示空态和两个记录入口，不要求先建立饮食计划。新建一餐默认入口日期与大致时间，餐名可修改，不强迫用户先分配早餐／午餐类别。向已有餐食添加内容时始终进入该餐，不另建重复餐食。

### 4.2 统一食物选择

```text
添加食物
├─ 一个搜索框＋整体食物分类＋一个结果列表
│  ├─ 未输入 → 浏览全部可用食物，常用优先
│  ├─ 选择分类 → 在该类内浏览／搜索
│  └─ 输入关键词 → 展示匹配食物，仍为同一列表
├─ 选择一个或多个食物
│  ├─ 填写当天克数或有基准的份量
│  ├─ 可以带出上次份量，随时修改
│  ├─ 营养按基准自动换算
│  └─ 所选内容保持，可继续寻找其他食物
├─ 常用标记【同一食物条目的轻量操作】
│  └─ 加入／取消常用只影响排序，不进入另一套模板页面
├─ 搜不到或来源暂不可用
│  ├─ 保留已经选择的内容
│  └─ 补充个人食物；无法取得营养时保持未知
└─ 加入当前餐食 → 保存当餐独立快照
```

“全部”通过连续加载或分页实现，不只是最近若干条，也不承诺全球食物完整覆盖。普通食物、菜品、包装食品共用分类和选择路径；品牌、熟生状态、做法等帮助区分具体食物，来源不变成独立搜索系统。

例：昨天早餐有包子、鸡蛋、豆浆；今天在同一列表选鸡蛋和豆浆，保留或改份量，再选夹馍。无需“复制昨天整餐”，也无需先进入“最近一餐”。常用标记承接用户最初希望主动保存常用食物的意图，具体图标和交互在实现时验证。

### 4.3 拍照识别

```text
拍照／选择照片
├─ 日期与大致时间【可修改】
├─ 一句说明【可选，如豆浆只喝了一半】
└─ 上传
   ├─ 尚未成功 → 显示进度；失败可重试，不称为已可靠保存
   └─ 已可靠保存到餐食
      ├─ 自动识别关闭 → 用户可手动发起
      └─ 已发起识别 → 可以离开页面
         ├─ 成功，餐食尚无已有手工或修正内容
         │  ├─ 形成单项食物与份量
         │  ├─ 自动保存并计入汇总，标记“照片估算”
         │  └─ 无误就不再操作
         ├─ 需要修正
         │  ├─ 份量不对 → 改份量，同步换算
         │  ├─ 食物认错 → 从同一食物库替换
         │  ├─ 漏了／多了 → 增加／移除单项
         │  └─ 整体识别错误 → 在原图有效期内重新识别
         └─ 失败
            ├─ 原图仍有效 → 原餐食重试
            ├─ 手动添加食物 → 保留已填内容
            └─ 原图已不可用 → 说明需重新选图，不承诺无图重试
```

- 鸡蛋与豆浆可分别记录，复杂混合菜可作为整道菜，不强行拆原料。
- 新分析遇到已有手工录入或修正时不自动覆盖；用户使用新结果前看到将替换的内容，未替换条目保留，覆盖内容不能重复计入。
- 追加照片或重试仍属于同一餐；多图内容重叠不能被当作多份餐食。
- 主界面不出现暂定采用、确认采用、候选版本或原图删除任务。保留上传、识别中、失败等对用户有意义的状态。
- 原图临时保留并按窗口清理；无需通过专门确认按钮才能结束保留。原图删除后，食物条目仍可查看、修改和复用。

## 5. 训练：计划与实际记录

### 5.1 页面主干与计划

```text
进入训练【日期默认今天，可切换】
├─ 训练计划
│  ├─ 查看当天安排
│  │  ├─ 名称、动作、顺序、目标量
│  │  └─ 动作指导【按需打开】
│  ├─ 修改当天安排
│  │  ├─ 增删／替换动作，改顺序和目标量
│  │  ├─ 只改变当天，不改可复用计划
│  │  └─ 已有记录时说明：实际不变，计划进度重新比较
│  ├─ 改期或取消安排
│  │  └─ 不移动或删除已有实际训练
│  ├─ 我的计划【次要入口】
│  │  ├─ 新建：空白／已有计划／实际记录／系统生成
│  │  ├─ 修改：用于之后复用，不覆盖已安排日期
│  │  ├─ 安排日期
│  │  │  ├─ 安排到一天，生成独立安排
│  │  │  └─ 连续安排 → 按周编排，各周允许不同
│  │  ├─ 直接用于记录，不必安排日期
│  │  └─ 删除：不连带删除已安排日期与实际记录
│  └─ 从当天计划记录 → 建立有关联的记录草稿
└─ 训练记录
   ├─ 当天已保存记录【按时间，多条允许】
   │  ├─ 日期／大致时间、动作和实际量摘要
   │  └─ 打开后修改或删除
   └─ 记录训练【主动作】→ 批量编辑
```

没有计划时可直接记录，没有记录时计划也独立存在。系统建议只在创建计划时出现；来源、周期单元等内部关系不成为首页并列概念。“我的计划”是可复用内容，“当天计划”是日期安排，不再使用方案／模板另一套名词。

例：周一和周四都安排“练胸”。周一临时调整只改周一；在我的计划里改动作，仅用于之后复用。只是周一实际少做时，只记实际，不要求反向改计划。

### 5.2 批量记录

```text
记录训练
├─ 日期、大致时间【可以补记】
├─ 选择基础
│  ├─ 今天／所查看日期的计划 → 关联该日期安排
│  ├─ 其他计划 → 复制内容，不自动安排到本日
│  ├─ 上次实际记录 → 复制动作和实际量，不继承旧日期关联
│  └─ 自己选动作 → 可一次选择多个
├─ 同一动作列表批量填写
│  ├─ 力量 → 组数 × 每组次数、重量
│  │  └─ 各组不同 → 展开调整
│  ├─ 自重 → 组数 × 次数，负重／辅助量按需
│  ├─ 计时／距离活动 → 适用的时长／距离
│  ├─ 没做 → 移除
│  ├─ 多做其他动作 → 添加
│  └─ 忘记数量 → 只保存知道的事实
└─ 保存记录【整条一次提交】
   ├─ 按计划做完 → 用户直接确认保存带出的内容
   ├─ 与计划不同 → 先改差异再保存
   ├─ 成功 → 更新训练、今天、历史
   └─ 失败 → 保留全部输入，允许重试
```

例如卧推默认一行“3 组 × 10 次，40 kg”；最后一组不同时展开改为“8 次，35 kg”。这只是填写便利，不是实时训练计数器。打开草稿不产生训练事实，也不出现“训练进行中”。

### 5.3 进度与关联

| 计划 | 实际记录 | 当天计划内展示 |
|---|---|---|
| 卧推 3 组 | 2 组 | 已记录 2／3 组 |
| 划船 3 组 | 3 组 | 已记录 3／3 组 |
| 跑步 20 分钟 | 无记录 | 未记录 |
| 动作只有名称、无目标量 | 记录了动作但未知数量 | 展示已记录内容，不伪造数量完成率 |

今天可概括为“按计划量：1 项完成，2 项尚未完成记录”，部分记录在训练页展开。该进度不表示重量、次数或训练质量达标，不混合组数与分钟计算百分比。

从当天计划记录自动建立对应；独立记录不靠同名猜匹配。多条有效关联记录累计，每条只算一次；超出量不抵扣其他动作。修改删除实际记录更新进度。修改当天安排后按新安排比较，旧依据保留后台，实际不变。

## 6. 历史：记录与趋势

```text
进入历史
├─ 记录【默认】
│  ├─ 按日期显示近期事实
│  ├─ 训练／饮食／身体筛选【按需】
│  └─ 打开一条记录
│     ├─ 训练 → 原训练详情／编辑
│     ├─ 餐食 → 原餐食详情／编辑
│     └─ 测量 → 我的／身体数据的同一记录
│        └─ 保存或取消 → 返回原历史日期与位置
└─ 趋势
   ├─ 身体：体重、腰围等实际测量变化
   ├─ 训练：记录次数／频率
   │  └─ 选择具体动作 → 看该动作适用指标
   ├─ 饮食：逐日已记录四项营养
   └─ 时间范围【次要选择】
```

训练频率表示保存的训练记录或有记录日期，具体指标标明单位，不把动作行数当训练次数。不画跨动作总量代表进步；饮食不输出缺少完整性依据的平均值、达标率或连续达标天数。缺失日期不补零。

历史不内嵌另一套完整编辑器，不默认展示修订版本、公式或跨模块 90 天大表。身体趋势入口指向或复用同一身体数据视图，新增测量稳定入口仍在我的。

## 7. 我的：个人功能与低频设置

```text
进入我的【摘要目录，不展开全部表单】
├─ 身体数据【稳定入口】
│  ├─ 当前体重／腰围及各自测量日期
│  ├─ 记录新测量 → 新增一次事实
│  ├─ 趋势与历史测量
│  └─ 修改／删除旧记录 → 纠错，不制造新测量
├─ 个人资料与目标
│  ├─ 基础资料 → 只修改并保存本项
│  ├─ 目标方向 → 条件性目标体重／日期
│  └─ 更多选项 → 特殊情况、适用营养偏好等
└─ 设置【低频】
   ├─ 通知与提醒
   │  ├─ 训练：当天有安排时按设置时间提醒
   │  ├─ 饮食：简单记餐提醒
   │  ├─ 身体：按周期提醒，可暂缓
   │  └─ 开启后才显示时间／周期，需要时申请通知权限
   ├─ 账号与数据
   │  ├─ 修改密码 → 验证当前密码
   │  ├─ 导出 → 发起后显示进度，完成下载
   │  ├─ 退出登录
   │  └─ 删除账号【危险区域，验证身份并二次确认】
   └─ 帮助与管理
      ├─ 问题报告 → 用户主动生成、预览、复制／下载
      └─ 系统管理【仅管理员，不可看他人健康记录】
```

每周新增体重不进入低频账号设置。拍照识别开关在饮食；训练计划在训练。资料和目标保存处简短说明从今天起影响新参考，不改写过去记录。提醒不推断是否已开始训练、是否全天记全或还剩多少营养。

## 8. 跨页、时间与草稿

| 场景 | 行为 |
|---|---|
| 从今天进入 | 默认今天；保存后留在相应业务页，今天摘要更新 |
| 从某日业务页进入 | 默认查看日期，过去日期明显提示 |
| 从历史改错 | 保存／取消返回原日期、筛选和位置 |
| 切换页面 | 保留草稿，回来续填；草稿不计入统计 |
| 保存失败／会话失效 | 保留输入，同一账号恢复后重试；不向另一账号显示 |
| 重复点击／网络重试 | 同次提交只生成一条事实，不双计营养或训练 |
| 多端并发修改 | 提示有更新并保留本地草稿，不静默覆盖 |
| 跨午夜 | 今天更新为新日期；现有草稿保持原日期 |
| 主动更改记录日期 | 更新原日期和新日期汇总，不把一次事实计入两天 |
| 补记身体测量 | 使用实际测量日期，不使用较晚的录入时间冒充最新值 |
| 修改测量备注／数值 | 不无故改变原测量时间，不新增一次测量 |
| 首次设置中断 | 已完成内容保留，继续未完成步骤 |

保留草稿不等于自动保存健康事实，也不承诺已完成离线同步或跨设备草稿。关闭浏览器后的持久草稿实现与隐私清理需在工程验收中确定，不能默认把健康明细写入长期浏览器存储。用户明确放弃时才清除当前草稿；退出、账号切换的草稿处理不能泄露另一账号数据。

## 9. 按需状态与后台边界

| 状态 | 用户看到 | 可以继续 |
|---|---|---|
| 空白 | 当前没有记录或安排 | 新增／选择 |
| 上传中 | 进度及尚未完成上传 | 重试或取消 |
| 识别中 | 该餐已保存、正在识别 | 离开或手动补充 |
| 识别失败 | 原餐仍在，是否可重试 | 重试／手动添加 |
| 营养部分未知 | 必要的整体提示，不逐项堆状态说明 | 继续使用或修正 |
| 参考无法计算 | 参考暂不可用及必要原因 | 记录不受影响 |
| 原图到期 | 需要重新选图才能再识别 | 已有食物继续编辑复用 |
| 保存冲突／失败 | 输入仍在，未宣称成功 | 恢复后重试 |
| 删除 | 明确当前目标与影响，避免默认连带删除 | 确认或取消 |

后台保留：账号隔离、临时媒体生命周期、任务重试与接管、幂等、来源与修订、计算证据与快照、备份恢复。不要求普通用户理解候选、采用状态、任务 ID、版本号或计算公式。
